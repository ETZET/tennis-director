## 正交 45° 相机怎么看山

屏幕竖直坐标 v = y·cos45° − (p·c)·sin45°（c = 朝镜头的水平方向）。几条推论决定了整个做法：

1. **远边**：v ∝ 高 + 离边距离 —— 越远、越高越往屏幕上走。三道山梁一道比一道远、一道比一道高，外坡陡于 45° → 一层压一层的剪影。
2. **地面没有地平线**：远边山脊后面 e 米的地面，e < 山高才被挡住，再远就从山顶上面"长"出来。第一轮的办法是地面只铺到最外一道山梁底下 —— 可那样近边（镜头这边）的地面也在那里断了，竖屏下面露出底。**第二轮换成"天幕"**（见下）：地面铺到 300 米外，远边山后面的地面被天幕挡掉。
3. **近边**：山顶只挡住"山高 − 山脊离边的距离（沿视线）"那么深。规则不变：山脚离 DESERT 那圈至少 1 米（`山高 ≤ (山脊离边 − 1) / (内坡系数 × 1.22)`）。用 `nearcheck.ts`（见下）在 yaw 0 / 38 / 128 / 218 / 308 五个方向逐个山脊点检查：**没有一个挡到 GROUNDS、两片停车场、高尔夫、车道，连 SITE 外沿都没挡到**。
4. **默认视角的预算**：横屏比 1.38 宽的画面都是竖向卡住。俱乐部缩 15% → 画面竖向多出 ~18%，顶上留 4% 的天，剩下给山。西北角正对镜头（屏幕上会所正上方），DESERT 的角在屏幕上已经快到原来的画面顶了，**那里"山高 + 离边距离"只放得下 ~40 米**；往西（屏幕左）、往北（屏幕右）地图边在屏幕上一路往下走，预算越来越大。所以"西北最高"落到画面上是：**西、北两边最高（52、48 米），在屏幕上左右两侧一直顶到天际线；西北角正中是一个矮鞍部（13 米），会所背后是一条窄的山梁带 + 一条天**。整幅是"盆地四周一圈山，背后一层层"，见「要定的」1。

## 天幕（`mtn:sky`）和两翼（`mtn:wings`）

- **天幕**：最外一道山梁每个截面的外山脚再往外 0.5 米，取**凸包**，立一圈竖直的带（−1 … 480 米），面朝里。材质只写深度、不写颜色、最先画（renderOrder −1）：远边那段正对镜头，它后面的地面、车道深度测试不过 → 露出背景的天；近边那段背对镜头被剔掉 → 近处地面一直铺到画外。外山脚离山脊 ≈ 0.7·山高 < 山高，所以天幕立在外坡里不多挡任何本来看得见的东西。法线 pass 写 `(0,0,1)` + alpha 0 → 不出轮廓线、凸边。
- **为什么是凸包**：凹进去的地方侧着看（clubpark / clubdesk 的 yaw 0 看东西两边）会有几段微微朝镜头，把圈里面的地面挡成一块天。
- **侧对的那几段丢掉**：着色器里水平法线和朝镜头方向夹角 > ~78°（`CURTAIN_FACING` 0.2）的片元 discard；yaw 0 时东西两边的凸包边就不挡了，否则会在山和外面的地之间切出一道天的竖缝。
- **两翼**：画面很宽（844×390 是 2.16:1）时，左右两边的视线从整圈山旁边擦过，碰不到天幕。从天幕在屏幕上最左、最右的点各往外拉一片正对镜头的竖直带（同一个材质），跟着镜头方位摆（`onBeforeRender`，方位变了才重算 12 个顶点）。锚点往远边偏 ~14°（比丢掉的侧对角度多一点）→ 和天幕在屏幕上接得上，没有缝。效果：画面两边是一条平的地平线（远处的谷地），上面是天。
- **保险**：天幕、两翼每帧把 `castShadow` 关掉（场景之后要是又对整棵树 `prepare`，480 米高的墙投影会把地图盖黑）。各场景都是 `prepare` 之后才加山，不受影响。
- clubmap2 的镜头 `dist` 260 → 520、`far` 560 → 1100：缩远时天幕上半截不被近裁剪面切掉。边缘检测阈值按米算，没变化。

## 三道山梁（第二轮）

每道沿 `DESERT` 往外偏 d 米（+ 按方向的 `dDir`）的圆角矩形（`LOOP_ROUND` 34）绕一圈，截面 5 个点（内山脚、内肩、山脊、外肩、外山脚），沿边每 ds 米一个截面。每个截面：

- 山高 = 八个方向的基准高（按外法线方位在东、东南、南……之间平滑插值）× 起伏（两层周期值噪声 0.55～1.2）；
- **天际线**：山顶在默认横屏取景（yaw 38°）里的屏幕高度 ≤ `skylineV − drop − band·(1 − 起伏)`。drop 让近的山梁比远的低一截（一层层），band 让山头、垭口在屏幕上也有起伏；最外一道最矮 `hMin` 8 米（不然沙地直接顶着天）；
- `jag`：山顶逐个截面往下抖 12～16% → 锯齿的天际线；
- 山脊进出 ±wander；山嘴 / 山沟（spur，内肩伸缩比第一轮大）；near、mid 是一段一段的（knobs，中间露出后面一道）；
- **垭口**（东边正对车道，|z| < 24 的截面）：mid 压成 1.2 米高、坡 1:7 的缓坡（两边两座山抬高 1.9 倍 → 山口），far 压成 5 米高的鞍部（内坡 1:4.5、外坡 1:2.4，两边抬高 1.5 倍）。垭口里不抖、不进出，车道 `passRoadGeo` 贴着它的面（`passY` 按同一个截面算）。

## 要定的

1. **西北角正中的山矮**：在"默认横屏顶上留一条天 + 俱乐部最多缩 15%"下，会所正上方（西北角）只放得下一个 ~13 米的鞍部，最高的山（西 53、北 48 米）在它左右两侧。想要会所正后方就是最高的山峰：要么俱乐部再缩（约 30% 才放得下 50 米的山）、要么允许那一处山顶冲出画面（那一段没有天）。
2. **竖屏的天太多**：竖屏横向卡住，竖向富余很多，现在地图居中 → 上面约 1/4 是天、下面约 1/5 是沙地。可以把地图往上挪（天少、沙多），或者竖屏默认方位从 62° 改成别的角度让远边的山更高。
3. **整圈看起来像盆地 / 火山口**：山梁贴着地图一圈，内坡连成一条环。要更像"背后一层层的山脉"而不是一圈，可以只在远边两侧（西、北）保留 mid / far、近边两侧（南、东南）几乎不要山（只剩远处的矮山）——代价是转到 yaw 218 时南边远边很空。
4. **西边的大坡面还是偏亮、偏平**（lum 量：左侧那块亮档占八成，里面含一点天）：不贴岩层的前提下只能靠截面再细（三角形翻倍）或者 bands 再抬，看用户要不要。
5. **两翼的地平线**：很宽的横屏（2:1）和转过去的方向上，整圈山的两侧外面是一条平的地平线 + 天（远处的谷地）。如果不想要这条线，只能让山梁在那两侧更宽、更远（又会碰到默认视角的预算）。
6. 竖屏 / 横屏缩到很远（zoom ≥ 0.6）能看到地面的圆角边（300 米外）——整个俱乐部那时只有巴掌大，暂时不管。
7. `clubpark/main.ts`（不归我改）区域标签"车道 → 往东出画"还对；第一轮说的 `sky-bridge` 分支还在。

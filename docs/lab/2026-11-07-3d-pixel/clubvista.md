用户看了《垂钓手记》的溪流地图视频（参考帧只在本地 `~/workspace/tennis-director-refs/fishing-notes-stream/`），
想让俱乐部的地图也做到"画面干净、地图好"。这一页按参考的地图搭法把俱乐部重新组织成四张主题小图，图和图之间走到出口 → 圆形遮罩转场。

## 参考的地图原则（brief：`~/workspace/tennis-director-refs/club-redo/brief/analysis.md`「地图怎么搭」）

1. 一张图一个主题，一两屏大；图和图之间转场（坐车 + 圆形遮罩 + 黑屏加载）。
2. 边界是自然的东西（密林、崖、水、马路、山），没有围栏和空气墙；**边缘最密、中间最空**。
3. 地形 2～3 层，层间朝镜头的崖做暗带；最安静的大面在最低层（参考是水，我们是球场）。
4. 路分主次、要弯：一条主路斜着弯过画面，支路通兴趣点。
5. 一张图 = 入口 → 目的地 → 歇脚。
6. 小场景讲故事、不靠字。

## 做法（代码）

| 文件 | 内容 |
| --- | --- |
| `mapdef.ts` | 一张图的数据形状：台面 Plate（高度 h、周围高度 base；h > base = 台地，朝外的崖从 h 下到 base；h < base = 坑，朝里的壁）、带子 Strip（主路 / 踏脚石 / 马路线）、台阶 / 小桥 Stair、平涂球场 Court、摆件 Prop、不能走的 noWalk、出口 Exit、入口 Entry；画轮廓的 `rect` / `band`（干河床、峡谷这种带）/ `blob` / `cluster`（3～7 个一簇） |
| `maps.ts` | 四张图（每张 28 米宽的核心 × 56～60 米深 + 两边各 15 米的边框） |
| `build.ts` | MapDef → 画面 + 导航：台面平滑、坑自动挖洞（只挖最外层的坑）、亮唇 + 崖壁（沙岩元素）、水面（带"到岸距离"的格子网格 + 一纹素白水线）、踏脚石、台阶、木桥、球场（外场 / 内场 / 白线）；摆件（本地资产 > 复用 > 白模）、默认挡路（树干圆、包围盒、有顶棚的只挡后墙）；0.25 米的高度格子（NaN = 水面 / 河床 / 密林） |
| `world.ts` | 页面：管线、太阳（阴影相机跟着总监、按阴影纹素对齐，同 clubwalk）、daylight、玩法（`clubsite/play`，按住走 / 点地面）、出口检测 → 转场、`?audit=1` 能走范围、`?labels=1` 白模标签 |
| （`iris.ts` 已删） | 圆形遮罩转场用 `clubsite/hud/iris.ts`（2026-11-26「合成一个游戏」） |
| `gallery.ts` | 资产画廊（上 / 左 2×，下 / 右放大 3 倍，1.8 米的人当比例尺） |
| `palette.ts` / `grade.ts` | 调色板（餐车院子、泳池、会员场、中心球场的超集 + 新材质）、默认配色 `vista`（午后金光的亮档 + 低彩度冷灰紫的暗档，只在这个页面） |
| `assets/` | 新画的资产；`reuse.ts` 只读复用别处的 |

四张图叠在同一块坐标上（`MAP_GAP` 0），只显示当前那张；换图时换导航的高度函数、挡路形状、坡道（`play.nav.setBlocked` 重建 0.2 米的网格，一张图 13.6 万格 < 15 万，A* 整图搜，不走粗网格的近路 —— 第一版四张图并排铺成 92 万格，长路线因为粗网格走廊找不到路）。

工具（`docs/lab/2026-11-07-3d-pixel/tools/`）：`vistashot.mjs`（一轮的 8 张截图）、`vistanums.mjs`（裁掉界面跑 hues + stats）、`vistawalk.mjs`（14 条路线：点地面寻路走过去、出口转场到哪张图）。

## 合成一个游戏（2026-11-26，clubgame）

用户看了分图和 clubwalk："这两个地图怎么没有合到一块？"。这一步把它们合成一个能玩的页面：**一个入口（`clubvista.html`，代码 `src/clubgame/main.ts`），一套像素界面，一套人物面板和演员表，一条能走通的路线，不换网址**。画面的美术（配色、材质、摆放）不动。`clubwalk.html` 原样能用。

**两个世界怎么同住一页。** 把 clubwalk 的整座俱乐部当第五张图"俱乐部内场"。分图和内场各有自己的画布（`#c` / `#cw`）、画面管线、总监、导航、像素界面、人物界面（都是 `clubsite` 的同一套代码，各挂一份），同一时刻只有一个在台上：另一个不走步、不画，画布和它往 body 上挂的界面 `visibility: hidden`（`clubgame/main.ts` 用 MutationObserver 记下每个世界挂了哪些界面元素）。共用的状态：

- 演员表的状态（钱、好感、记忆、游戏时钟）是同一个盒子（`createCastStore`）；
- 时刻和天气（两个世界各有一个 `daylight`）在换世界的那一刻抄过去；
- 换世界的圆形转场、小地图是 clubgame 自己的一份（不属于哪个世界）。

内场第一次进去才加载、才建（动态 import，在转场的黑幕里建，约 1～2 秒，黑幕上写"加载中…"）；之后留着，来回只是换台。

**为什么不把两套世界揉进一个场景。** 两边的配色方案（分图 `vista` 冷影子 / 内场 `golden`）、太阳高度、导航（分图四张图叠在同一块坐标上换高度函数；内场按区域走到哪建到哪）、daylight 的天色都不一样，揉进一个场景等于重写 clubwalk，画面也一定会变；这一步的约束是不动美术。两块画布各画各的，画面一个像素不变，clubwalk.html、valley.html 不受影响。**为什么不是两个页面跳转。** 单文件 demo 只能是一个页面；跳页要重新加载（3～5 秒白屏），状态得全走 localStorage / 查询串。代价：内场建好以后页面里有两个 WebGL 上下文（显存大约翻倍，手机上要留意）；界面元素是两份（看着一样）。

- **两边画面不协调**：分图是冷影子的 `vista` 配色、有崖和台地 2～3 层；内场是午后金光、地面是平的、影子偏暖紫。转场前后色调跳一下。人的密度也差很多（前台只有一两个人，内场大门里一堆人）。

- **总监的活和动作键**只在内场有（分图里只有"说话"）。
- **名册和小地图互不认识**：名册不标每个人在哪张图，小地图的牌子上不标人数；内场在小地图上只是一块牌子（没有展开成分区、不标大门在哪）。
- **分图的镜头在图的下沿夹住**：开局总监在画面偏下的地方；人物卡升起来时会盖住总监和对面的人（内场里镜头跟得住）。取景范围是地图那一步按构图定的，没动。
- **第 3 轮评判剩下没改的**：进图的地名（上方淡出的一行，像素界面原来的位置）会压在中心球场的记分牌上、练习场里压在总监身上；点人以后上方那行字出现时，场景里没有标出是哪个人（开了人物卡才有箭头），内场人多时第二下不知道点谁；动作键第一次出现时的说明小牌盖住圆键本体；转场黑幕右下角的三个小点（iris 的加载点）意思不明。都是 `clubsite/hud` 共用的部件，改了 clubwalk、valley 也跟着变，留给界面那条线。
- **出口没有画在场景里的记号**（路牌、拱门）：现在靠界面的小路牌和踏脚石。去内场的那串踏脚石有两块在烟树的影子里，不显眼。
- **两个时钟**：日钟跟的是 daylight（一天走得很快），人物卡、名册用的是演员表的游戏时钟（1 秒 = 1 游戏分钟）；合成以前 clubwalk 就是这样，等游戏流程（M-0）定了一起收。走一圈钱和天数不变，没有"今天该干什么"、收盘结算——都是 M-0 的事。
- **性能**：内场建好以后两个 WebGL 上下文同时在；第一次进内场主线程要卡 1～2 秒（黑幕里）。没在真手机上量过。

**踩到的坑**（写给以后画分图的人）：
- **寻路一步只认 ≤ stepUp / 2（0.16 米）的高差**（`clubsite/play/nav.ts` 的 A*；连续走路认 stepUp 0.32）。果岭第一版领草在 0.25 米，草地 0 → 0.25 一步迈不上去，果岭成了寻路找不到的孤岛（点上去会停在边上）。多级的台面每级 ≤ 0.15，或者用台阶 / 坡道（Stair）。
- 同高的两块台面重叠会互相打架（锯齿、横纹）：里面那块压低 0.02 米、让外面那块挖洞。
- 下到坑里的台阶要越过坑沿一点，正好停在坑沿时寻路找不到路。
- 摆件的 `userData.setFill` 不一定是观众（保洁车、回收站也有）。
- 七个子代理同时开浏览器截图，机器负载到过 170～250，截图超时；同时最多两个。

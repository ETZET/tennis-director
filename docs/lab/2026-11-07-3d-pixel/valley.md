# valley：俱乐部所在的小镇和山谷（地图扩张 demo）

2026-11-15 开始。页面：`/valley.html`（3D 白模，能走、能开车）、`/valleyplan.html`（平面图）。代码在 `apps/sandbox/src/valley/`。

## 为什么做

用户觉得地图太受限，两层意思：

- **广度**：只有一个围墙圈起来的俱乐部，一个门，墙外什么都没有。
- **深度**：每个场景能干的事少，布局规整（球场全东西向排成两列、路全是直的十字），一眼看完、很好猜。

## 用户定的方向（2026-11-15）

- 做到**俱乐部所在的小镇和山谷**，大到需要跑图；**分区解锁**。
- demo 形态：**3D 白模能走**；俱乐部那块直接用 clubwalk（只读引用），其余白模。

## 版图

见 `layout.ts` 顶上的注释和 `/valleyplan.html`。要点：

- 西边圣哈辛托山一整面山墙，小镇贴着山脚；俱乐部在西南角的山湾里（原来 clubsite/mountains 那圈山换成山谷的山，湾口朝东）。
- 棕榈谷大道南北贯穿（市中心和印第安峡谷路是一对单行道），北出山口变 111 号公路去风车田；塔奎兹峡谷路东西向去机场。
- 塔奎兹溪干河床从山里的峡谷（尽头瀑布）斜穿山谷；美术馆步道从市中心背后爬到观景台（山上唯一能走的地方）。
- 小区是弯路、小环、死胡同；两座高尔夫、两片椰枣园、机场、废弃的老球拍俱乐部。
- 平地 ≈ 2.2 km²（俱乐部围墙内的 190 倍）。俱乐部 → 市中心沿路 1.2 km：走路 6 分、球车 3 分、汽车 1.2 分。

## 技术

- **clubwalk 抽成 `mountWalk(hooks)`**（`clubwalk/walk.ts`；`clubwalk/main.ts` 不带钩子调，行为不变）。山谷的钩子：丢掉底图的山、底图只留俱乐部那块（`CLUB_BOX`）、外面的地能不能站（`outerSurface`）、挡路形状、地名、小地图、每步的演出。
- **导航**：0.2 米的寻路网格铺 2 km 要几千万格，铺不下 → `NavSpec.grid` 让网格只铺俱乐部那块，`bounds` 管整座山谷（连续移动按形状实时判断，本来就不靠网格）；网格外的点地面走 = `farPath`（先在网格里走到车道东头，再直着走）。
- **开车**：`Play.drive({ speed, turn })` —— 同一个拖动手势，更快、拐弯慢；汽车只能在路上（`vnav.mode`）；开车时俱乐部的门挡上；镜头拉远（球车 1.45×、汽车 2.1×）。
- **锁着 = 暗**：几何按（区域, 材质）合并，锁着的区域整片换压暗的材质；路口按锁的状态摆路障；锁着的区域不能站。
- **山**：高度场（12 米一格，24 格一块切开剔除），按离平地的距离长高；南边的山坡度 < 45°（镜头朝北俯 45°，南坡高过距离就挡人）。
- **细节模块**：`detail/town.ts`、`south.ts`、`east.ts` 一片区域一个文件（并行做），拿 `DetailCtx`（put / instance / block / rng / regionOf）。

## 第二轮：画面审查（2026-11-16）

用户试玩以后说"完成度很低"：方块式的阴影、路上莫名其妙的东西、傍晚太阳闪、还有许多画面不合理的地方。第一轮只看了几张正午截图就当验收，是流程的问题。这一轮：

- **硬门槛验收脚本** `tools/valley-accept.mjs`：控制台零报错；路面（车道收 0.4 米、离地 0.15～4 米）零顶点；7 / 17.6 / 18.3 点附近细扫不闪（相邻两步亮度差 ≤ 3%）；俱乐部外绘制 ≤ 700、三角形 ≤ 450k；强边缘 ≤ 0.05；正午饱和度 ≥ 0.35（站在车道上的点只提醒）；俱乐部里 4 个点和 clubwalk 同点同时刻对照（≤ 基线 + 1.5%，关云影和风）。天气固定晴天。
- **傍晚整屏闪**的根因在 clubsite/daylight：傍晚着色仰角下限 30°，平地亮度 sin 30° = 0.5 正好压在色阶的"中|亮"档位线上 → 下限改 33°（所有接了时间系统的场景都受益，clubwalk 原来也闪 23%）。
- **山**不投影不受投影（原来受影 → 投影相机边上切出硬边块）；网格改成三档精度 + 三道山梁三个色阶。
- 五个 subagent 分文件审查：山、底子（build / layout / vehicles）、市中心、南边和河床、东边和学校公园；每个交问题清单 + 修前修后对照。共找到约 150 条，修了约 120 条。
- 教训：门槛要防"为了过数字而改错"（底子把沥青染成石板蓝去凑饱和度，远看像河 → 改回，车道上的点只提醒）；对照要先量基线（人、喷泉、云影、风会动）。

最终验收（28 个点 × 3 个时刻）：只剩"机场正午饱和度 0.331"一条没过（锁着的东谷，路口沥青 + 航站楼墙，留到做机场时）。

## 第三轮：整体缩小（2026-11-16）

用户："路有一点点太长，适当缩短"，选了整个山谷缩小。layout.ts 加了 `S(x, z)`：俱乐部那块（CLUB_BOX）不动，别的位置往俱乐部门口 (140, 0) 压到 0.7；只压位置，不压大小（路宽、楼、球场照旧）。layout 的数据照原尺寸写、模块末尾统一过 S；别的文件里手写的坐标都过 S。平地 2.2 → 1.1 km²；俱乐部 → 市中心 1198 → 863 米（汽车 54 秒）。挤不下的东西收边或删掉（市中心停车场剩一块、高尔夫 6 → 4 洞、两架飞机、公园看台），不叠着放。观景台随步道变短降到 36 米（坡 0.3）。

最终验收全过（28 个点 × 3 个时刻 + 闪烁 + 俱乐部对照），18 条饱和度提醒（0.35～0.42）。

## 第四轮：市中心三栋办事楼 + 店内（2026-11-16）

- 外观：报社（西班牙复兴、《沙漠太阳报》报头）、体育用品店（TENNIS PRO SHOP）、五金大超市（芥末黄 + 深蓝，停车场能开进去）。关卡 1 灰盒 → 用户定版图和配色 → 关卡 2 每栋一个代理画素材（`detail/sites/`、`assets/`、画廊 `/valleyassets.html`）。细节和三栋的版图见 `valley-town.md`。
- 店内（设计稿：https://claude.ai/artifact/RqDAYjwUum7gF5AKsBo6Gw；报社按用户简化成办事点）：进门换场景，店内是封闭的空间、按玩法放大（`interiors/`：局部坐标 + 框架画地板墙门，摆在地图外 x ≥ 3000）。
  - 室内状态按总监**在哪**切（走门、传送、at= 都一样）：背景暗色、镜头关在房间里并拉近、光照定住（`daylight.override`：没有日夜天气、`sunK 0` 不投影）、没有云影。
  - 店里寻路：每间店一张 0.4 米的小网格（`nav.ts` 的 interiorPath）。
  - 配色：用户说"和外景太像"→ 三家各一套，并量化：屋内沙 / 桃一族 ≤ 20%、和门外街景 ΔE ≥ 25、三家互相 ΔE ≥ 20。报社深色老编辑部（墨绿、茄紫褐地板、牛血红），体育店冷亮（天蓝地胶、蓝墙），五金深灰绿环氧地坪（用户选）+ 深蓝货架 + 芥末黄横梁。
  - 每家导出 `SPOTS`（互动锚点），下一关做推车、叉车、穿线、找总编等互动。

## 第五轮：店内第二版（2026-11-16，`?inv=2`）

用户看了 Sneaky Sasquatch 的店内截图（参考图只放本地，不进仓库），要求"保留目前的 demo"、照启发做第二版。两版并存：`interiors/all.ts` 按 `?inv=` 只建一版（默认 v1），v2 在 `interiors/v2/` + `assets/in2/`（资产 `in2-*`），共用件 `interiors/v2/kit.ts`（价签、"…"气泡、大字分区条、地面字框、5×7 / 3×5 像素字）。

从参考图学到的七条：镜头近、人大、东西少而大；能买的东西下面挂价签（走过去点就买）；分区靠大字条；人在柜台后、能说话的头顶冒"…"；地和墙是平的大色块、每家一个主色调；区域用地上的大字框；进门正对主墙、柜台在门边、过道直而宽。

- 镜头：`InteriorDef.zoom`（米/纹素 = 进山谷时的默认 × zoom）。v1 0.8，v2 0.4～0.45；手机竖屏总监 ≈ 80～93 像素高、横着看得到 ≈ 7.5～9 米。山谷的 zoom 下限 0.5 → 0.4。店里隐藏小地图。
- 尺寸：报社 14 × 12、体育店 18 × 14、五金 36 × 22（v1 是 20 × 16、30 × 24、80 × 50）。
- 每家导出 `SPOTS`（互动锚点）和 `ITEMS`（带价签的可买的东西，局部坐标 + 价钱）：报社 12 / 3，体育店 23 / 25，五金 20 / 40。
- 验收（`VALLEY_EXTRA=inv=2 valley-accept.mjs`，9 个店内点）全过；三家屋内平均 Lab 互相 ΔE 24～35、和街景 ≥ 26。
- 没到的："细变化"0.03～0.09（目标 0.17～0.21）——近镜头 + 平涂大色块的必然结果，店内近景不再用这条门槛。

## 第六轮：店内去掉字（2026-11-19）

用户看了第二批（市政厅、银行、餐馆）的店内："look at sasquatch reference, let the layout and visual do the explanation, not the subtext." 对照参考图：Sneaky Sasquatch 的办事处、银行、餐馆店内几乎没有字 —— 横贯的柜台分开员工和客人、隔离柱 = 排队、红箭头出票机 + 数码屏 = 取号、桌上的汉堡和调料瓶 = 餐馆；地是安静的中性面，颜色在东西上；人是谁看打扮和手边的东西。第五轮的原则 3「分区靠大字条」、6「地上大字框」是从电器店、仓库两张图过度推广的，作废。

- 规矩：店内零字（只留数字、图标、看不清的线）；每个玩法点靠一件认得出的东西 + 布置；能聊的人靠打扮和道具；地板安静（去掉"店内互相 ΔE"那条门槛 —— 它把地板逼艳了）。验收加"零字检查"和"读图表"（玩法点 → 靠哪件东西认出来）。
- 第二批三家先改（PR #43），再改第一批的第二版三家：
  - 报社：报头 → 太阳图标牌；ARCHIVE → 旧头版本身（版面线、标题色块、照片块，铜牌只刻年份）；CLASSIFIEDS → 钉满纸条的板 + 打字机；前台 → 服务铃 + 报纸摞；加了 4 条 talk。
  - 体育店：RACQUETS / SHOES / APPAREL / STRINGING / BALLS / BAGS / PAY HERE → 东西本身 + 图标圆牌（鞋、T 恤、线轴）；USED → 循环箭头牌 + 白吊牌；TRY ZONE → 迷你球场地垫。
  - 五金：分区字条 → 图标牌（小球场、喷头、滚筒刷、木方、羊角锤）；LOADING ZONE → 卷帘门前黄黑斜纹；FORKLIFT → 黄框车位；CHECKOUT → 只亮"1"的通道灯。
- 验收（`VALLEY_EXTRA=inv=2`，15 个店内点）：全过，屋内正午饱和度 0.41～0.47，强边缘 ≤ 0.018；`pnpm check` 全过。门外的报社 0.289、五金 0.349 没过 0.35 是小镇缩小以后的旧问题，这一轮没碰。

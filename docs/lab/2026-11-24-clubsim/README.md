# 俱乐部的一天 · 实验记录

2026-11-24 起。设计见 [docs/design/club-sim.md](../../design/club-sim.md)。

用户的要求：俱乐部里的会员、员工、访客由一个真在跑的引擎驱动（几点来、在哪、干什么、中午吃饭、晚上回家），画面跟着引擎；
没有画面的事再补。配一个专门的 critique agent，做几轮 loop。最后交一个 artifact：山谷 demo 的"调试"面板里有"观察俱乐部的一天（加速）"。

## 工具

| 工具 | 干什么 |
| --- | --- |
| `pnpm simday [--day N] [--seed S] [--director desk\|none] [--people a,b] [--json]` | 引擎跑一整天，打印每小时人数、各区域、排队、放弃、抽样的人的一天、不变式 |
| `node docs/lab/2026-11-24-clubsim/tools/simshot.mjs` | 手机竖屏截图：几个时刻 × 几个地点 + 全图；量每帧的耗时 |
| `node docs/lab/2026-11-24-clubsim/tools/spotcheck.mjs` | 每个站位在世界导航里站得住 |

## 循环

每一轮：

1. **critique**（独立的 agent，不改代码）：跑 `pnpm simday`（平日、周末、夏天、总监不在前台各一次），跑 simshot，读截图，按下面的评分表写 `round-N/critique.md`：
   问题按"对用户看到的效果影响多大"排序，每条写现象、证据（数字、截图路径）、建议的改法、归哪块（引擎 / 地点站位 / 画面 / 面板）。
2. **lead 分诊**：挑这一轮要改的，按文件归属分给修的 agent（不重叠）。
3. **修**：修完各自跑测试和工具。
4. **lead 复验**：重跑工具，对照上一轮的数，写 `round-N/result.md`（改了什么、分数变化、留下的）。

## 评分表（每项 0–5）

| | 看什么 |
| --- | --- |
| R1 节奏 | 每小时人数曲线像不像一座真的沙漠网球俱乐部：清早员工先到、早场、午饭高峰、午后热的低谷、放学的青训、晚场、关门走光 |
| R2 一个人的一天 | 抽 10 个人读：先后顺序合理、时间长短合理、一伙人一起、等待和放弃有原因；named 会员按 people.md 的来访日 |
| R3 地方用得对 | 每个地点的占用说得通（场地早晚满中午空、摊位午饭排队、躺椅下午满、长椅有人歇）；没有永远空着的地方，也没有一直爆满的 |
| R4 画面对得上 | 截图里的人数、位置和引擎一致；没有人站在墙里、网上、水里（游泳除外）、桌上；姿势和在干什么对得上；人不扎堆、不滑步、不瞬移 |
| R5 看得懂 | 加速看的时候，不看面板也能看出"现在是午饭""这伙人刚到""那个人等烦了"；观察面板在手机上好用 |
| R6 性能 | 60× 时每帧引擎 + 演出 < 4 ms；手机竖屏不掉帧 |

缺画面的活（游泳、健身、吃饭……）不扣分，列进 gaps，排进"要补的画面"。

# 2026-11-04 可玩性实验：11 个玩法 demo

打开 [`index.html`](index.html) 看总览（手机竖屏的格子页，每张卡点进去就能玩）。每个 demo 是一个独立的 HTML 文件，不依赖游戏代码，双击就能在浏览器里打开；手机上看最好（390×844 竖屏）。

**这一轮不改游戏代码。** demo 是一次性的原型，用来挑方向：文字直接写在页面里、数值随手定、不走 sim。选中以后再按 CLAUDE.md 的分层正式做。

## 目标：可玩性的北极星

> **每 20–40 秒有一个玩家自己想做、而且有取舍的决定；每 3–5 分钟有一次"赚到了"或"搞砸了"的高光；一局结束，玩家能说出"我是一个怎样的总监"。**

拿这三条给每个 demo 打分（总览页每张卡上有一句话说明它在测哪一条）：

| 尺度 | 问题 | 现在的游戏 |
| --- | --- | --- |
| 20–40 秒 | 有没有一个**想做**的动作？做之前会犹豫吗？ | 只有"把人拖到红色 +"。几乎不用想：空着就填。 |
| 3–5 分钟 | 有没有一个让人笑出来或骂出来的时刻？ | 修好一处设施时有一点；其余时间是数字慢慢涨。 |
| 一局 | 两个玩家的俱乐部会长得不一样吗？ | 修复顺序是固定的，选路刚开始做；钱基本只有一个去处（材料费）。 |

## 诊断：为什么"加了这么多东西还是不好玩"

1. **只有一个动词。** 拖人。拖完以后结果是一个数字，玩家没有"怎么干"的余地，也看不出干得好不好。
2. **决定没有张力。** 红色的空位就该填；好岗位和坏岗位的区别只是基数。准则 2 要求的"取舍"大多压在事件卡上，日常操作里几乎没有。
3. **钱没有好玩的去处，也没有好玩的来处。** 收入是"有人在岗 × 基数"，玩家不能定价、不能卖东西、不能决定招什么客人；花钱只有材料费。经营游戏最核心的"低买高卖、薅一把、被反噬"没有。
4. **客人是抽象的。** 会员是一个数，服务率是一个比例。看不到一个具体的人因为你的决定高兴或者骂人。
5. **拖完没反馈。** 拖到岗位上，只有一个环形进度。没有"这个人适合这里"的手感，没有放错的代价被立刻看见。

## 三根新支柱（这一轮 demo 按这三条分组）

### A. 奸商：钱从哪儿来

让玩家对**价格、商品、会籍、时段**动手。经营的乐趣来自"我比客人多算一步"，以及偶尔算过头被反噬（差评、退会、上报纸）。

### B. 总监亲手干：小游戏

总监本来就是一个劳动力。与其"把总监拖到穿线台"，不如让玩家**亲手穿一次线、画一次线、推销一次会籍、打一场挑战赛**。小游戏做得好，结果更好；但总监的时间只有那么多，去做小游戏就不在别处（取舍还在）。

### C. 人的手感：重做排人

拖人本身不是问题，问题是**拖之前不用想、拖之后没感觉**。三种替代：给拖动加足反馈和匹配度；换成"一天的拼图"；或者干脆让玩家直接控制总监跑来跑去（像 Diner Dash）。

## 怎么挑

1. 手机上每个玩 3–5 分钟。
2. 每个打一个分：**还想再玩一局吗？**（0 不想 / 1 无所谓 / 2 想）。只看这一条，不用管画面粗不粗。
3. 回复里告诉我：哪几个 2 分、哪几个想合并（比如 01 + 04 是同一个"店"）、哪几个完全不要。
4. 我按你的选择做第二轮：把选中的玩法放进 Palm Oasis 的真实画面里做一个整合 demo，再决定要不要改玩法准则（比如 C 组会动准则 5，A 组会动"收入只看在岗"这条）。

## 和玩法准则的冲突（先说清楚）

**制作人 2026-11-04 定：这一轮不怕违反玩法准则。** demo 以好玩为准，下面只是记一笔，方便选中以后知道要改哪条：

- **09 一天的拼图**是一种排班画面，违反准则 5 括号里"没有日程表画面"（ADR 0012）。
- **10 总监跑场**把总监从"可指派的劳动力"变成玩家直接控制的角色，节奏也从放置变成手忙脚乱，会动准则 6 的"不操作时世界照样运转"。
- **A 组**让收入取决于价格和商品，而不只是"有人在岗"；会员也会因为定价当场流失，不再只在周日结算。
- **B 组的小游戏**是一个新的操作层，不是卡也不是拖人；按准则 1 它是"直接和场景里的东西互动"，应该不冲突，但要防止变成每天必做的流水线（准则 4 的"偶发、有分量"）。

选中以后，冲突的那条准则要先写 ADR 再改。

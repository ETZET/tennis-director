# demo 共用简报（每个 demo 的 agent 先读这份）

## 背景

《网球总监》是一款手机竖屏优先的 2.5D 等距像素网球俱乐部经营游戏：玩家是总监，接手加州沙漠里废弃十年的 Palm Oasis 网球俱乐部（Indian Wells, CA），把它修回来、经营起来。老员工 Dale（老教练，60 多岁，戴棒球帽）陪着你；后来能招到 Rosa（维护工，沙漠长大）、Ben（前台，早起）、Jess（教练，干劲足）、Gus（维护工，完美主义但心累）、Lily（前台，双语夜猫子）、Teodora（穿线师）等人。

用户（制作人）觉得现在的游戏可玩性太低：唯一的动词是"把员工拖到岗位上"，拖完没什么反馈，决定也没有张力。这一轮要做 10 个**能上手玩的玩法 demo** 让他挑方向。总目标见 `../README.md`（北极星：每 20–40 秒一个有取舍的决定，每 3–5 分钟一个高光，一局能说出"我是怎样的总监"）。**不受现有游戏代码框架限制**，你只做一个独立原型。

## 硬性要求

- **一个文件**：`docs/lab/2026-11-04-playability/demos/<你的目录>/index.html`，HTML + CSS + 原生 JS 全部内联。不引用任何外部资源（没有 CDN、字体、图片文件、网络请求），`file://` 双击就能跑。不 import 仓库里的任何代码。控制在大约 800–1800 行。
- **手机竖屏优先**：按 390×844 设计，`<meta name="viewport" content="width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no">`，`touch-action: none` 防止拖动时滚页。操作放在屏幕下半（拇指区），点击目标至少 44 px。只用 Pointer Events（pointerdown/move/up），不依赖 hover 和键盘；桌面打开时居中显示一个 390 宽的手机框即可。
- **中文界面**（这是一次性原型，文字直接写在代码里没关系）。
- **能玩完一局**：3–5 分钟一局，有开始（一屏 2–4 行的"怎么玩"，点一下开始）、有过程、有结束画面（成绩、一句话评价玩家是什么样的总监、"再来一局"按钮）。开一个随机种子，每局有点不同。
- **右上角一个"?"按钮**：打开设计说明浮层（这个 demo 在测什么假设、取舍在哪里），再点关掉。
- **反馈要足（这是用户最在意的）**：每个操作都要有即时、看得见的回应——数字飞出来（+$12 绿、−$5 红）、人物冒表情气泡（😊😠💢💤 用像素画或简单字符都行）、屏幕轻微抖动、闪光、计数跳动、音效可选（WebAudio 合成的短"哔"，默认开，左上角一个静音按钮）。玩家放错/定错要立刻看到代价，做对要爽。
- **取舍**：不能有一个各方面都更好的选项（玩法准则 2）。在 notes.md 里写清楚每个主要决定换来什么、付出什么。

## 画面风格（和游戏一致：像素等距/像素俯视）

- 用一个低分辨率 `<canvas>`（例如 195×422 或 130×281 的逻辑像素）画场景，CSS 放大 2× 或 3×，`image-rendering: pixelated`。UI（按钮、卡片、数字）可以用 DOM 盖在上面，DOM 用圆角奶油色面板、深色描边、粗体系统字体，有点 Kairosoft 的感觉。
- 人物是像素小人，大约 8×14 像素（含深色描边），用字符串数组写成字符画（例如 `'..OOOO..'`），按字母换色（皮肤、头发、上衣、裤子），至少有站立和走路两帧，朝左时水平翻转。场景可以是等距（2:1 菱形）或者正俯视，按你的玩法选更清楚的。
- 调色板（尽量从这里取色）：
  - 描边/墨色 `#2a1f2b`，奶油面板 `#fff4dc`，面板描边 `#5a3d2b`
  - 沙地 `#e8c88a` / 暗沙 `#c9a36a`，天空 `#8ec9e8`，远山 `#b98a6a`
  - 硬地场蓝 `#3f6fb0` / 场外绿 `#4f8a4b`，红土 `#c8643c`，场地白线 `#f4f1e8`
  - 棕榈绿 `#3c7d3a`，泳池 `#4fc3d9`，木头 `#8a5a35`，屋顶 `#a8453a`
  - 金色强调 `#f2b134`，警告红 `#d94a3a`，钱绿 `#3fae5a`，皮肤几种 `#f1c27d #c68642 #8d5524 #ffdbac`
- 有一点沙漠的生活气：棕榈、风滚草、太阳、远处的山都可以点缀，但别让装饰抢了玩法。

## 交付物（只写你自己的目录，不碰仓库里任何其他文件；不要 git commit）

1. `index.html`：demo 本体。
2. `notes.md`（中文，简洁）：
   - 一句话：这是什么
   - 怎么玩（3–6 条）
   - 在测的假设（对应北极星的哪一条）
   - 取舍表：每个主要决定换来什么 / 付出什么
   - 反馈清单：哪些操作给了什么反馈
   - 如果选中，怎么接进现在的游戏（接在哪个设施/岗位/事件卡上、和"总监是劳动力""周日结算"等现有系统怎么拼）
   - 和玩法准则的冲突（准则原文见仓库根目录 `CLAUDE.md` 的"玩法准则"）
   - 已知不足 / 第二轮可以加什么
3. 截图：用 `node docs/lab/2026-11-04-playability/tools/shot.mjs docs/lab/2026-11-04-playability/demos/<你的目录> 1500` 存 `shot.png`（开始画面或第一屏）；再写一个交互脚本（放在你自己的目录下，例如 `play.mjs`，`export default async (page) => {...}`，用 `page.mouse` 或 `page.touchscreen` 点开始、做几步操作、等几秒），用 `SHOT_OUT=<你的目录>/shot-2.png node .../shot.mjs <你的目录> 1500 <你的目录>/play.mjs` 存一张**正在玩**的截图。脚本会打印页面报错：**必须是 "ok, no errors"**。用 Read 工具看一下两张截图，确认画面清楚、文字没被截断、按钮在拇指区、像素是放大后清晰的（不是糊的）。看到问题就改了重截。
4. 最后回复里用 5–8 行写：做了什么、一局大概多久、你自己觉得最好玩的瞬间是什么、最弱的地方是什么。

## 质量标准

- 先保证"好玩的那 30 秒"是真的好玩，再加别的。宁可少一个系统，也要把一个循环做透、反馈做足。
- 数值随手定，但要让一局里出现至少一次明显的"赚到了"和一次"搞砸了"。
- 自己用脚本把一局从头玩到结束画面至少一次（可以在脚本里加速，例如页面支持 `?fast=1` 把时间放快），确认不会卡死、不会报错、结束画面能出来。

# 主游戏迁到 Indian Wells · 优先级和待办

2026-11-01 · @Enting

目标：把新的经营循环（拖人上岗位、一次性工单、修好设施解锁岗位、招人）跑在 Indian Wells 这张地图上。**画面先用灰盒**，精细的废弃场景（Palm Oasis 改造版）放到最后。

> **2026-11-01：P0 和 P1 完成，#6 和 #7 已合进 main。** 这份计划到此结束；剩下的 P2、P3 和新的待办都搬到了
> [backlog.md](backlog.md)，按界面、玩法、逻辑、美术四条轨道拆成任务（编号见下面各表的"状态"一栏）。现在的玩法见 [game-design.md](game-design.md) v0.3，决定记在 [ADR 0016](../adr/0016-single-map-site.md)。
> 和下面草案不一样的地方：失败条件改成"第 112 天期限到了"或"现金跌破 −$2000"；表演赛带判定，冷场一周后可以再办；
> 没有做单独的试训（招聘日卡上已经公开了能力和周薪，见 ADR 0016）；"幕"只去掉了继承，名字留着。
> 平衡：贪心型机器人 99% 在第 91–111 天办成表演赛，从不招人的谨慎型 0%，随机型 0%（`docs/balance/indian-wells.md`）。

- **游戏画面写死在 Hollow Creek 上。** `apps/game/src/main.ts` 和 `scene.ts` 直接引用 `hollowCreek` 的锚点、站位、地面高度、相机、灯光、设施覆盖层和天空。
- **缺的系统：** 招聘日 / 试训、总监能力成长、新的终点和失败条件、沙漠天气。
- **PR #6 还开着。** 单独合进 main 会让游戏、模拟测试和机器人跑局全挂。

## 当时建议的默认值（实际采用的见 game-design.md）

这些在设计文档"待定问题"里还没定。P0 先按下面写内容，之后改 YAML 就行，不用动代码。

| 问题 | 建议 |
| --- | --- |
| 员工种类 | 三种，对应现有三项能力：**场地工**（维护）、**教练**（教学）、**球童 / 前台**（服务）。 |
| 开局能用的地方 | 入口和停车场能走；**会所里 Dale 那间办公室**能待；**外场 1** 勉强能用（扫沙、换网两张工单做完就开出第一个持续岗位"外场 1 · 租场"）。其他全部是坏的。 |
| 修复顺序（草案） | 外场 1 → 外场 2、3 → 练习场 → 会所前台（开出服务岗位和招聘日）→ 广场喷泉和餐饮 → Stadium 3 → Stadium 2 → Stadium 1。越往后越贵，前一项修好才能修下一项。 |
| 终点（MVP） | 修好 Stadium 1，办一场表演赛 = 通关。 |
| 失败（MVP） | 现金连续 4 周为负 = 园区被卖掉。 |
| 招聘日 | 会所前台修好后开放，每 2 周一次，每次 3 个候选人。 |
| 总监成长 | 每完成一圈岗位或一张工单，对应能力 +0.5，上限 80。 |
| 节奏 | 一局 12–16 周（游戏内），第一次招人在第 2 周左右。 |

## 零、一句话

玩家布置好岗位以后放下手机，园区里的人该像有自己的日子：球员开门就去练球，维护工先去看最破的那块场，老会员周一早上准时出现在会员场门口，没人接待的客人等烦了掉头走。**他们做的每件事都是一个玩家看得懂的信号；他们是谁决定他们做什么；他们之间有几条看得见的牵连。**

## 一、五条原则

1. **三层人，三种精度。** 有名字的员工（已有）每人一条状态；**常客**（有名字的会员，新）每人一条状态，有每周的来访模式和一段短记忆；**人群**（会员、学员、周末客人）不记个体的一生，只记此刻在哪、等了多久、要去干什么，池子有上限。
2. **行为是信号。** 每一种自主行为都对应一个玩家关心的事实：维护工往哪儿跑，哪儿就要掉档；球员在哪儿练，那块场就空着；客人掉头走，就是没人接待。点场景里的人，看到一行他"在想什么"（i18n），不开面板。信号说档不说数（"红土场快要掉档了"，不是"状况 23"），和 ADR 0022 的口径一致。
3. **不流于随机。** 每个人按"性子 + 一天的模板"行动：同一个人在同样的处境下总做同样的事。随机只用在候选同分时打破平局，而且用 `s.seed` 派生的哈希，不碰主随机流。玩家应该能说出"Rosa 每天早上先去红土场"。
4. **自主行为有产出，但是排人的一小截，而且有代价。** 这是对玩法准则 5 的改写（ADR 0028），写进 `CLAUDE.md` 的措辞：

   > 5. **日常经营靠招人和排人。** 提升会所靠玩家主动把人（总监也是一个可指派的劳动力）拖到场景里的岗位和工单上；没有日程表画面，排班藏在随时拖动里（ADR 0012）。没排的人按自己的性子找事做（ADR 0028）：那是信号，不是经营。产出只有排人的一小截，永远不会替玩家修好一处设施、带完一堂课或收一分钱。

   数值：按正式岗位同一公式算，乘全局系数 `idle_k = 0.2`，所有倍率乘完以后截在 `idle_cap = 0.5`。空闲产出只有球技、短期脏乱、疲劳三种，**不碰设施状况、现金、会员、声望**。空闲练球比正式练球多出疲劳（+3/小时），这是它的代价。
5. **关系只做成对的规则。** 不做社交网，每条关系是"两个人都在、满足某个处境 → 看得见的行为 + 一个小数值或一张卡"。每条都进因果日志。关系里要有摩擦，而且摩擦在第一版就要有代价，不能只是士气。

### 招聘日的结构决定了谁和谁能有关系

每个招聘日只排一张卡，卡上二选一或不招；a / b / c 三拨是三张不同的卡，每局只来一拨（`iw_hiring_day_*.yaml`）。所以：

- **同一招聘日的人互斥**，不管同拨还是跨拨：Rosa / Ben；Jess / Gus / Kofi / Amara；Luca / Walt / Teodora / Lily；Nadia / Marco / Ray / Mateo / Diego。Marco 在 4a 和 4c 两拨里都有，仍然和第 4 日的其他四人互斥。
- **拨由路线决定**：★2 选青训，招聘日 2、3 来 a 拨的概率 0.8；选度假，来 b 拨 0.8。招聘日 4 的 c 拨（Diego / Marco）在没有球员的局 0.5、有球员的局 0.2，c 优先于 b。
- **两人都被招到的概率**（按路线匹配、每张卡二选一各 0.5）：一人每局都在（Dale、常客）、另一人在本路线 0.8 的拨 → 约 0.4；两人都要招、同路线 → 0.8 × 0.8 × 0.25 ≈ 0.16；跨路线 → 0.8 × 0.2 × 0.25 ≈ 0.04。关系表的可达性按这个数分档：**高 ≥ 0.2，中 0.08–0.2，低 < 0.08**。
- **时间**：招聘日 1 约第 22–28 天，2 约第 36–42 天，3 约第 50–56 天，4 约第 64–70 天；一局第 83–112 天结束，贪心型表演赛中位第 92 天、九成当场交账。招聘日 4 来的人只剩 2–6 周。
- **机器人**（`docs/balance/playability.md`）：贪心型固定招 Rosa / Gus / Luca / Marco 或 Ray，2b 时招 Amara（27%）、3b 时招 Lily（13%）；从不招 Ben、Jess、Walt、Nadia、Mateo、Kofi、Teodora。谨慎型一个人都不招。平衡闸口要补一种"招聘卡全选另一侧"的打法，不然这七个人的卡和关系没有跑局数据。

所以关系只写跨招聘日的人之间，以及和 Dale、总监、常客之间；一局里能同时成立的员工关系通常 4–7 条，常客关系另算。可达性低的关系只做风味，可达性高的关系才配卡。

## 二、骨架：数据和系统

全部在 `packages/sim`，纯数据、可序列化、按锚点不按坐标。画面只读状态、只订阅事件。

```ts
export type Verb = 'practice' | 'spar' | 'watch' | 'mentor' | 'inspect' | 'tinker' | 'greet' | 'rest' | 'chat' | 'wander' | 'off';

/** 空闲去处：这个人此刻自己决定在干什么 */
export interface Intent {
  verb: Verb;
  at: string;            // 锚点；off = parking（画面层对到达的 off 隐藏精灵）
  with?: string;         // 一起的人（对练、聊天、带练）
  since: number;         // 定下这个去处的时刻（"巡场 30 分钟后"从到达起算）
  until: number;         // 绝对游戏分钟，到点重选
  settled: number;       // 上一次结算空闲产出的时刻（每 10 分钟结一次，中断丢零头、不退回）
  bank: number;          // 未取整的累计球技产出；≥ 0.01 或 intent 结束时一次写入（growth 全部 round2，不攒会永远涨不动）
}
// PersonState 加：intent?: Intent | null；role 枚举（schema）加 'regular'：常客进 s.people，hired: false
// 一个 id = 一个 PersonState = 一个精灵。夫妇是两个 id，共用一张 RegularState；Sofía 是 Verónica 的 escort（纯画面跟随精灵，不进 s.people）

/** 员工和访客都能走：walk.ts 的 plan / walkTo / walkSystem 泛化成 planFor(w, t, mover, to) / walkMover(ctx, mover, to) / walkSystemFor(ctx, movers, onArrive)；
 *  原来按 id 的版本保留并发 personDeparted / personArrived；walkpath.ts 的 locate 只认 Walk，不用改 */
export interface Mover { at: string; walk: Walk | null }

/** 访客个体（人群层）：有目的、会等、会走。不进 s.people */
export interface Visitor extends Mover {
  uid: number;
  purpose: string;       // 要去的岗位 id；锚点就是岗位的 at
  group: number;         // 一起来的几个人（家庭 2–3，联赛队 4）
  state: 'arriving' | 'waiting' | 'served' | 'playing' | 'leaving';
  since: number;
  patience: number;      // 等多久走人（分钟）
}

/** 常客的旁表；pair 的两个人共用一张（key 是 pair 名） */
export interface RegularState {
  favor: number;                       // 好感 0–10，开局 5
  memory: boolean[];                   // 最近 4 次来访有没有被接待
  gone: boolean;                       // 不再出现（只由卡或剧情记号触发）
  visit: { plan: string[]; step: number; since: number; served: boolean } | null;  // 这一次来访依次去的岗位
  flags: Record<string, boolean | number>;
}
// GameState 加：regulars: Record<string, RegularState>; visitors: Visitor[];
//   crowd: Record<string, { playing: number; waiting: number; served: boolean }>;
//   week 加：friends?: number（常客带来的朋友，周日结算成会员，准则 6）
```

**事件**（`events.ts`）：

```ts

| { type: 'visitorArrived'; uid: number; purpose: string; at: string; group: number }
| { type: 'visitorLeft'; uid: number; purpose: string; at: string; reason: 'served' | 'patience' | 'closed' }
| { type: 'regularVisit'; regular: string; at: string; purpose: string }
```

### 和现有系统的交接

- **谁会被 `intentSystem` 处理。** 在职员工（不含总监）里满足：没在走路、没在办事、没有记着的工单（`resume`），并且 `job === null`，或者 `job` 是一个有时段的岗位而此刻不在时段里（班关着）。在工单上、在"随时"岗位上（维护）、在开着的班上的人不动。必须这样写，因为习惯系统在班关着时**保留** `job`（员工条显示"下一班 15:00"），否则所有有习惯的人在时段外都算"有岗位"，模板一条也不会触发。
- **回班是 `intentSystem` 自己的事。** 带着关着的 `job` 出去的人，习惯系统不会送他回去（`routineTarget` 看到"手上的班开了"就返回 null，`occupant` 仍然是他，别人也不抢），岗位会被一个在外面练球的人占着。所以每 10 分钟检查：`job` 是有时段岗位且 `开班时刻 − 现在 ≤ shortestRoute(p.at, post.at).minutes + 10` → `clearIntent` 并 `walkTo(post.at)`（`job` 不变，不发 `routine` 事件）。
- **不耽误下一班（准则 6）。** 新增 `nextShift(s, w, id)`：从 `pin`、有时段的 `job`、`routine` 里取今天还没开始、`postExists` 的最早一班（`project.ts` 的私有 `nextShift` 改为调它）。选候选时要求 `shortestRoute(候选地点, 下一班地点).minutes ≤ 下一班开始 − 现在 − 10`；下一班前 30 分钟只选本地点的候选或 `rest`。
- **谁清掉 `intent`。** 习惯到点（`routineSystem` → `assign`）、玩家拖人或叫停（`assign`）、事件叫人（`sendErrand`）、回班，四处都调 `clearIntent(ctx, id)`：先把 `bank` 写进球技，清自己；若对方的 `intent.with === id` 一并清掉对方；发 `intent: null` 事件。带练是单向的（教练 `with` = 球员，球员的 `practice` 没有 `with`），所以**倍率不存，结算时现算**：`with === 我 && verb === 'mentor' && at === 我的 at && !walk` 的教练里取最高，同分按 id。`intent` 不像 `leaveJob` 那样作废：产出每 10 分钟结一次，中断只丢不满 10 分钟的零头。
- **配对。** 两人"各自重选"会出现 A 想和 B 对练、B 想和 C 对练。按 `staffIds` 排序遍历，排前的人选搭档时同一趟写两人的 `intent`（互为 `with`），排后的人这一趟跳过。
- **`idleMin`。** `idleSystem` 忽略由 `intent` 发起的走路（`p.intent && p.walk?.to === p.intent.at`）；这只对 `job === null` 的人有意义（带着关着的 `job` 的人本来就不算闲），`iw_dale_nudge` 的触发对象不变。
- **系统顺序。** `intentSystem` 放在 `staffSystem` 最后（`orderSystem` 之后，复用 `jobIndex`）：每 10 分钟先结算上一段的产出，再对到点的人重选；每趟开头建一次 `Map<anchor, ids[]>` 给关系配对用。`crowdSystem`、`regularSystem` 放在 `activitySystem` 之后。
- **产出的写法。** 球技不走 `growStaff`（它按 `growth.rates` 固定步长，而且 `play` 不在 `growth.skills` 里）。`growth.ts` 加 `growBy(ctx, id, k, amount)`：上限是成长打开时的潜力、否则 100，`round2` 后写入，再 `noteSkill`。`pr_training` 的效果不动。疲劳是整数，不用 `bank`。
- **空闲产出不写 `s.ledger`**，否则 `staffedToday()` 会把顺手修算成"有人守"，收盘衰减再打对折。
- **常客进 `s.people`**（`role: 'regular'`，`hired: false`）：复用走路、`LOOKS`、气泡；`canAssign` 看 `isStaff`（按 role）所以不会被派活、不进员工条、不算 `hired.*`、不算工资和士气漂移；`sendErrand` 只看 `hired`，常客叫不走。`scene.ts` 决定显示谁的那一行从 `p.hired` 改成"常客看 `regulars[id].visit !== null`"。`scene.test.ts` 要求所有人物都有 `LOOKS`：常客每人一个。
- **Tommy 的奖学金**不靠 `wage_week`、不写 `kind`（`PERSON_KINDS` 没有学生）：flag `tommy_scholarship` + `rules.stipends: [{ flag: tommy_scholarship, week: 30 }]`，`bookDay` 把 `week / 7` 记进 `week.money.wages`，周结算一行"奖学金"；他 `hired: false`、`role: regular`，上不了岗位。
- **访客不进 `s.people`**：`Visitor` 自带 `walk`，走 `walkMover` / `walkSystemFor`。
- **随机。** 人群到达、常客来访的抖动、候选同分全部用 `s.seed` 派生的哈希，**不消耗 `s.rng`**：现有种子的天气和抽卡完全不变。`hash01(...n: number[])` 只收数字，字符串先过 `hashStr`（FNV-1a 过 UTF-16 码元）：同分 `floor(hash01(seed, day, slot, hashStr(person), hashStr(verb)) × n)`；到达 `hash01(seed, day, slot, hashStr(post))`；访客耐心抖动用 `uid`。
- **夜里。** `overnight()` 把所有 `intent` 置空（先写 `bank`），常客的 `visit` 置空，访客池清空。
- **第二季。** `startSeason2()` 清 `visitors`、`crowd`、`regulars[*].visit`，保留 `favor` / `memory` / `gone` / `flags`，常客按新一季的日子重算来访。
- **存档。** 每一期上线时 `SAVE_VERSION` 加一；期一的迁移：`people[*].intent = null`；期二 `visitors = []`、`crowd = {}`；期三 `regulars = {}`，`regularSystem` 第一次运行时按内容补缺的常客（迁移函数拿不到内容）。
- **HUD 不改来源。** "有 N 处客人在等"继续按需求分钟算（`postDemand`），服务率也是；`crowd` 只给 `life.ts`。访客到达有抖动，某个 10 分钟没人来不等于没需求（准则 6）。
- **因果日志。** 空闲产出不逐条写；周结算加一行"园区里的事"（`ui.week.park`）。人物快讯每天最多 2 条，多的并进周结算那一行。关系触发的卡照常进日志。
- **卡的节流（准则 4）。** 人物和常客的卡全部 `source: threshold` 走导演抽（受 `gap`），另加 `rules.people_cards_per_week = 2`；超出的排队到下周。纯奖励的"时刻"不做卡，做**快讯**（`log` 效果）。卡 schema 加 `rare: boolean`，sim-cli 报告"从未出现的卡"那一行跳过它，并单列"稀有卡出现率"。

### 行为模板的解析规则

- 每个人先继承作用的默认模板（`behaviour.yaml` 的 `templates.<kind>`），再用自己的 `day` 覆盖。`day` 的每一项可以带 `hours: [a, b]`（小数小时，例如 `[15.5, 20]`），不带就是时段名的默认区间（上午 8–12、中午 12–13、下午 13–17、傍晚 17–20）。解析时按顺序取**第一个** `hours` 包含此刻的项的候选列表（整段覆盖，不逐条合并）；没命中的时段继承作用模板。
- 候选按顺序取第一个此刻成立的；同一 `rank` 的并列用种子哈希打破。候选里写了 `when` 就**替换**这个 verb 的默认条件（Dale 的 `inspect` 中心球场不看状况，就是这样写的）。
- `off` 是一个候选 `{ verb: off, at: parking }`：人走到停车场，画面层对已到达的 `off` 隐藏精灵。`off` 优先于天气覆盖。
- 天气覆盖是把候选**前置**到模板前面，不是替换；只改 `intent`，不动习惯、岗位、工单。统一写法 `weather.<rain|wind|heat>.<kind|all>: { hours?: [a, b], then: [...] }`。
- `rest` 没有前置条件（它是兜底）；疲劳 ≥ 60 时在每个模板最前面插一条 `{ verb: rest }`。
- 关键字锚点：
  - `worst_open`：状况 < 60、没在改造、锚点上至少一个岗位 `postExists` 的设施里状况最低者，同分按锚点名排序；没有就这条不成立。
  - `dropping_soon`：`状况 − dayDecay(...) < rules.grade_drop_below`（15）的设施。
  - `lesson_live`：教学岗位里 `postInHours && occupant && working(occupant)` 的 `at`；多个取最近。
  - `craft_post`：`only` 含本人手艺特质且 `postExists` 的岗位的 `at`；没有手艺的特殊岗位人物（Ben、Lily）这条不成立、顺延。
- `practice` 的"场地空着"：锚点上没有正在 `working` 的**有时段**岗位的人、`s.activities` 里没有占着这个锚点的活动、可用度不是"不能用"（ADR 0022）。`pr_training` 是随时岗位、`only: player`，别的球员在上面不挡。期二起再加 `crowd.playing == 0`。
- Marco 在内容里是 `kind: crew`，他"傍晚按特殊岗位模板走"必须写在他自己的 `day` 里。

### 内容

- `people/*.yaml` 每人加 `day`；常客也在这里（`role: regular`），加 `pair`、`escort`。

- 编译器校验：`verb` 在 `verbs` 里；`at` 是幕的锚点或关键字；时段名在 `{morning, noon, afternoon, evening}`，`hours` 在营业时间内；`regulars[*].visits[*].plan` 的每一项是存在的岗位；每个 verb 两种语言都有文案且占位符一致；`rare` 只能出现在 threshold 卡上；role 枚举加 `regular`。
- `COMPUTED_VARS`（两边一致，走 `compile.ts` 的三段式校验）：`visitor_left.<post>`（本周按岗位累计走掉的组数，对岗位表校验）、`regular.<id>.favor` / `.present` / `.gone` / `.missed`（`REGULAR_ATTRS`）、`idle_hours.<person>.<verb>`（累计空闲时长）、`crowd.waiting`（固定表）。
- 新效果（白名单 + schema）：`{ favor: <regular>, add: n }`、`{ regular: <id>, gone: true }`、`{ regular: <id>, flag: k, set: v }`。"泳池维护效率 +10%"这类不加新效果，用 flag 加岗位效果里的表达式实现。

## 三、行为词典

`verb` 的全集。产出都已经乘了 `idle_k = 0.2`，所有倍率乘完以后截在 `idle_cap = 0.5`（正式岗位的一半）。**一名球员同时只有一个带练的人，倍率取最高。** `spar` 的倍率和 `mentor` 天然互斥（`mentor` 只在 `practice` 时触发）；`practice` 上的乘子（Kofi、Amara–Luca）会和带练相乘，靠 `idle_cap` 截住。

| 动作 | 谁会做 | 去哪 | 条件 | 产出和代价 | 演出 | 点人时的话 |
| --- | --- | --- | --- | --- | --- | --- |
| `practice` 自己练 | 球员 | 空着的青训场；没有就外场 2–3；都没有就会员场 | 场地空着（上一节的定义） | 球技 +0.02/小时（正式岗位 0.1）；疲劳 +3/小时；不加磨损、不加脏乱 | `training` | "自己练着。没人看，涨得慢。" |
| `spar` 对练 | 两个球员；或球员和球技 ≥ 45 的教练 | 同一块空场 | 两人都空闲 | 各 +0.04/小时；疲劳各 +3/小时 | `rally` | "和 {with} 对练，比一个人对墙强。" |
| `watch` 看课 | 教练、球员、常客 | 正在上课或有人练球的场边 | 那里有人 | 无 | 站位：场边 | "看 {who} 上课。" |
| `mentor` 带练 | 教练 | 球员正在 `practice` 的场边 | 教练空闲、球员在练 | 球员这段时间倍率 ×2，"带徒弟"×4；教练疲劳 +5/小时 | `lesson` 的教练帧 + 头顶图标 | "在给 {with} 看步法。" |
| `inspect` 巡场 | 维护工 | 开着的设施里状况最低的一处 | 状况 < 60（`day` 里可改） | 无；点他能读到那处的档："快要掉档了 / 还撑得住" | 蹲下摸地面 + 🔍 | "{place} 快要掉档了，再不管就是一张重开工单。" |
| `tinker` 顺手修 | 维护工（巡场 30 分钟后） | 同一处 | 那里有短期脏乱（ADR 0022 的球和垃圾） | 清脏乱 ×0.2；**不碰状况**（否则一个闲着的维护工就把设施钉在状况 50，掉档和打扫工单都不会再出现） | 扫沙、收球 + 🔧 | "顺手收拾一下。要修还得正式派他来。" |
| `greet` 招呼客人 | 服务类的人（前台、服务 ≥ 45 的任何人） | 有需求而没人在岗的岗位地点 | 期一：`postDemand && !occupant`，纯画面；期二起：那里 `waiting > 0` | 期二起：那处访客耐心 ×1.5；不算接待、不产生收入 | 站到队伍前 + 👋 | "先跟客人打个招呼，没人收钱。" |
| `rest` 歇着 | 任何人 | 棕榈喷泉；会所开着就会所；泳池开着就池边 | 无（兜底）；疲劳 ≥ 60 时前置 | 疲劳 −2/小时 | `idle.ts` 的 `sit` + Zz | "坐一会儿。" |
| `chat` 聊天 | 两个人（见关系表） | 两人中离得近的那个地点 | 关系规则成立 | 见关系表 | 对站 + 💬 | "{a} 和 {b} 在聊 {topic}。" |
| `wander` 走走 | 任何人 | 开着的地点里轮一处 | 以上都不成立 | 无 | `idle.ts` 的 `stroll` | "没事，走走。" |
| `off` 不在 | 模板写了的人 | 停车场 | 模板 | 无 | 到了就隐藏 | "回家了。" |

常客和访客另有自己的状态机（第六、七节），不用这张表。总监没有自主行为：他是玩家的手，站着就是站着。

**玩家怎么看见（390×844）。** 精灵约 20 px 高，`watch` / `greet` / `chat` / `inspect` 在画面上都是"站着或蹲着的人"，只有 `practice` 和 `spar` 天然可辨。所以每个有信息量的 verb 一个头顶像素图标（`SpriteLayer` 的像素表情通道）：🔍 🔧 👋 💬 Zz，`mentor` 是眼睛加拍子；`watch`、`wander` 不给图标（本来就是"没事"）。**点人一行话**：员工的那一行就是员工条上 `doing()` 的小字，加 `ui.staff.intent.<verb>` 分支，几乎零新界面；场景里再冒一个 3 秒气泡。常客和访客只有气泡。场景里点人物精灵的命中半径 ≥ 22 CSS px；手上拿着人时点人物忽略（不是落点）。

## 四、作用的默认一天

| 作用 | 上午 | 下午 | 傍晚 |
| --- | --- | --- | --- |
| 球员 | `practice` → `spar` → `watch` | `spar` → `practice` | `practice` → `rest` |
| 教练 | `watch`（有课的地方）→ `mentor` → `rest`（会所） | `mentor` → `watch` → `spar` | `watch` → `rest` |
| 维护工 | `inspect`（按状况从低到高走两处）→ `tinker` | `tinker` → `inspect` | `inspect`（看明天要掉档的）→ `rest` |
| 特殊岗位 | 自己手艺的地点 → `greet` | `greet` → `rest` | `greet` → `wander` |

天气：**下雨** 全员室内（会所开着就会所，不然棕榈喷泉的棚子），不练不巡；**大风** 维护工直接去外场 2–3（最积沙），别人照常；**酷热**（ADR 0022）中午 12–15 点球员不练、改 `rest`。酷热在 ADR 0022 里"不关场、不改别的数"，这里只是行为层。

## 六、常客

常客是会员数的脸。他们有名字、有固定的来访模式、有好感（0–10，开局 5）和四次来访的短记忆。**好感只影响耐心、带朋友和卡，不碰收入**（第九节列出的例外除外）。经济主线仍是需求分钟。

常客的状态机：到点从大门或停车场出发 → 按 `plan` 依次走到目的岗位的地点 → 那里有人在岗：`served`，好感 +0.1，待满时间去下一站；那一站的岗位没开（设施没修、不在时段）：跳过；没人在岗：等，耐心 = 基础值 × (0.5 + favor / 10) → 等到人：`served`，好感不变；等不到：这一站记"没见到人"，好感 −0.5，连续两次 −1。记忆四次里有三次没见到人 → 他们的卡（卡的某个选项可以让他们 `gone`）。`gone` 只由卡或剧情记号触发，不由好感自动触发，不然会员场刚修好、只有总监和 Dale 在做工单的那两周，老会员一周就走光了。好感 ≥ 8 的常客每次来访 10% 概率带一个朋友：记进 `week.friends`，周日和会员一起结算，周结算里单列一行（准则 6）。`gone` 时会员 −2，因果日志一条；如果是从一张已经扣了会员的卡走的（`iw_pickle_noise` 的 C），不再重复扣。

## 十一、需要拍板的事

1. **`idle_k` 取 0.2 还是 0.1。** 0.2 是"看得见涨"，0.1 是"几乎只是演"。建议 0.2，第一期跑完平衡报告再定。
2. **Owen 的预付卡。** 它让 ★3 的选路多一个"钱的理由"。金额订在 $800 是故意让它不够决定性；如果评审觉得它污染了选路，可以改成只影响第二季的报价、不预付。
3. **Ortega 夫妇的旧钥匙。** 他们自己开门打球不算服务率缺口，也不产生收入。另一个做法是算缺口（更严），但那样他们就和普通访客没区别了。建议不算。
4. **Verónica 的第五个名额。** 她的卡让走过 4b 又没选 Mateo 的局多一个 $70 的人。它只在那种局出现，而且 Mateo 是全场最便宜、普通活最慢的人；但它确实突破了"一局最多招 4 个人"。建议保留，并在平衡报告里单看这类局。
5. **常客要不要在员工条里出现。** 建议不要：他们不是你的人，只在场景里和周结算里出现，点他们有一句话。
6. **碰经济的七条例外**（第九节）要不要全留。最可疑的是 Teodora 的 +3% / +5% 和 Owen 的报价；它们是特质和常客的效果，不是空闲产出，但确实让"不排人也有好处"多了两处。

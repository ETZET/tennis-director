# 人物：3D 俱乐部里的人

2026-11-13 · 第一版。从 2.5D 时期的人物模拟（`docs/archive/2.5d-game/docs/people-sim.md` v3、`people.md`）净化而来，改写到 3D 场景上。决策见 [ADR 0030](../adr/0030-people-cast.md)。
契约在 `apps/sandbox/src/clubsite/cast/types.ts`（冻结）和 `traits.ts`；人物的故事以 `cast/named.ts` 为准，本文不重复长篇故事。

本文定四件事：**场景里每一个人是谁**（演员表怎么叠在演出上）；**一个人有哪些数据**；**总监怎么和他们打交道、付出什么**；**人和人之间有哪些牵连**。

## 零、一句话

俱乐部里的人该像有自己的日子：老会员周一早上准时出现在红土场，候鸟夫妇风季一到就收拾回北方，咖啡吧的小本记得每个熟客喝什么。
**他们做的每件事都是一个看得懂的信号；他们是谁决定他们做什么；他们之间有几条看得见的牵连；总监要走到跟前才能和他们打交道。**

## 一、原则

从 2.5D 版留下来的四条方法论，加一条 3D 的。

1. **三层人，三种精度。** `named` 有名有姓、手写故事（员工、老会员、常客、他们的家人）；`regular` 有名字、有属性、按模板生成的熟面孔，有每周的来访模式和一段短记忆；
   `crowd` 今天的客人，属性齐全但没有故事，只管此刻：来干什么、等了多久、还能等多久。三层都是完整的 `CastPerson`：**场景里出现的每一个人点开都有身份和属性。**
2. **行为是信号。** 每一种看得见的行为都对应一个玩家关心的事：谁在排队跺脚，哪儿就没人管；老会员自己动手开门，就是没人接待；长椅上的人皱眉走掉，就是广场脏了。
   点场景里的人，看到一行他"在想什么"（按他此刻在干什么挑台词），不开面板。信号说档不说数（"排好长……"，不是"等了 14 分钟"，ADR 0022 的口径）。
3. **不流于随机。** 每个人按"性子 + 每周的模式"行动：同一个人在同样的处境下做同样的事、说同样的话。生成、选角、挑台词、互动结果都用种子哈希，不用 `Math.random`。
   玩家应该能说出"Ortega 夫妇周一、三、五早上八点在红土场"。
4. **关系只做成对的规则。** 不做社交网。每条关系是"两个人都在、满足某个处境 → 看得见的行为 + 一个小数值"。**摩擦一开始就要有代价**（耐心、好感、心情），不能只是一句台词。
5. **人物是叠在演出上的一层（3D 新加）。** 场景的 `life.ts` 照旧演，演员表只回答"这个位置今天是谁"。演出不决定数值，演员表也不决定动画：一期两边互不读，二期起演出跟随演员表。

## 二、怎么叠到 3D 场景上

### 现在场景里的人

场景里的人由各场景的 `life.ts` 按脚本演（演出时钟 + 种子随机流 `ctx.rng(...)`），不进模拟、不存档。clubwalk 把 11 个场景连起来，区域按"看得见就建"，
一共约 238 个 Q 版人（含相邻区域建了但藏着的副本；同一个槽位名可能在两个区域里各有一份，**以没藏的那份为准**）。

| 场景 | 建出来的人（含藏着的） | 谁 |
| --- | --- | --- |
| `clubpark` 停车场 | 5 | 代客、门童、下车 / 取车的会员 |
| `clubdesk` 前台 | 15 | 前台、排队签到的会员、水站边的人 |
| `clubpickle` 匹克球场 | 30 | 双打四人、拍架前排队的、伞下的观众、路过的 |
| `clubplaza` 喷泉广场 | 15 | 饮料车摊主、长椅上的会员、拨水的孩子和家长 |
| `clubstadium` 中心球场 | 17 | 两名职业球员、裁判、六个球童、场边的人（看台观众是实例化的剪影，不是人） |
| `clubcourts` 会员场 + 青训 | 18 | 教练、四个孩子、家长、会员双打、发球机前的少年、帆下等场的 |
| `clubclay` 红土场 | 9 | 近场双打、裁判、观众 |
| `clubhouse` 会所三层 | 40（不在的楼层藏着） | 店员、咖啡师、穿线师、酒保、厨师、服务员、健身的人、前台、洗衣工 |
| `clubpool` 泳池 | 16 | 救生员、游泳和池边晒太阳的、孩子 |
| `clubgolf` 高尔夫 | 6 | 打高尔夫的 |

清点用 clubwalk 的调试钩子 `window.__clubwalk`（`eager=1` 建好全部区域再遍历）；每个位置是什么人写在 `cast/slots.ts`，依据是各场景的 `layout.ts`（SLOTS 的注释）和 `life.ts`。

### 叠法：位置 → 人 → 样子 → 信息

```
场景里的一个人（userData.isPerson、personKind、poseName()）
  → 位置：scene + slot（'slot:<id>' 去掉前缀；演出临时建的人 = '#<n>'，区域里第 n 个没有槽位名的人，按建的顺序从 0 数）
  → 演员表 who(scene, slot, kind, day)：这一天这个位置是谁
  → CastPerson
  → 换装（clubsite/people/dress.ts 按 CastLook：肤色、发型、帽子、衣服、配饰、体型；制服 keep 的部位不动）
  → 名字小牌、属性、"在想什么"（按 poseName() 推断的 Activity 挑台词）
```

**选角顺序**（`who`，`cast/casting.ts`）：

1. `named` 的 `homes` 里有这个位置、`days` 对得上（不给 `days` = 每天）→ 他；
2. 员工位置（员工、摊主、教练、球员）named 没占的日子 → 一个固定的 regular 员工顶上（每天都是他，不换人）；
3. `regular` 熟面孔（约 90 个，每人一周来 1–5 天、偏好一两个场景）今天来 → 占一个合适的位置，同一个位置优先（习惯）；
4. 剩下的位置 → 今天的客人：按 `种子 + 场景 + 槽位 + 天` 生成（id `guest:<场景>:<槽位>:<天>`），**同一天同一位置永远是同一个人**，换一天换一个人。

不变式：同一天同一位置只有一个人，一个人一天只在一个位置，位置的种类、身份和人的体型、身份对得上。
画面这边（`clubwalk/cast/bind.ts`）每 0.5 秒扫一遍看得见的区域，把人对上演员表、记下 `castId`，id 变了才换装（每帧有预算，区域刚建好分几帧换完）。

**身份和场景要对得上。** 每个位置有一张 `SlotInfo`（`cast/slots.ts`：场景、槽位、人的种类、身份、一个短词说他在干什么）。kid 槽位只放孩子（`body: 'kid'`），
ball-kid 槽位放少年（`teen`），coach 槽位放教练，umpire 槽位放裁判；员工位置穿制服（第三节）。

**一天。** demo 有自己的时钟（`CastState.day` / `minute`，营业 7:00–22:00，第 1 天是周一；1 真实秒 = 1 游戏分钟，`?castspeed=` 调，名册里有"下一天"），只用来换天：
过了 22:00 进下一天，重新选角、重新换装（换人群、算周几），清"今天说过几次话"。状态存在 localStorage（`?castreset=1` 清掉，`?cast=0` 整个关掉）。
它不是 M-0 要定的"一天的结构"；场景的演出照旧按自己的循环跑，不跟着这个时钟。

### 通勤：人从真的出入口来、到真的出入口去

各场景的演出是按"单独一个场景"写的：人从画面边上走进来、走到画面边上藏起来，过一会儿再从那儿出来。连成整座俱乐部以后，
那些"画面边"落在了地图中间（广场长廊两头、前台西边、匹克球场西边、美食广场的四个口子），人就在路中间凭空出现、消失；
循环路线走完直接放回起点的人，会在画面里瞬移。场景的演出不改（单独的场景页面还要它），大世界这一层接管（`clubwalk/cast/commute.ts`）：

- **消失**：演出藏起一个人的那一刻，那里不是出入口 → 一个长得一样的替身接着走，沿整座俱乐部的导航走到**他前进方向上**最近的出入口
  （进了大门的人接着往里走到会所，不掉头回停车场），到了再消失（上车、进门）。
- **出现**：演出亮出一个人的那一刻，那里不是出入口 → 先藏着他，替身从最近的出入口出来追上他（他照演出继续走；落后多了替身走快，最快小跑），
  追上了换回真人。这会儿没有路（他在还没建好的区域里）就先等，隔一秒再试。
- **瞬移**（一步挪出去 2 米以上）：当成在旧地方消失、在新地方出现。刚走开又被演出叫回来的人：正在离开的替身掉头追回去交接。
- **出入口**：停车场里停着的车尾那一侧、会所的门、泳池围栏的三道门。停车场里、落客点（上下车、代客泊车）、会所里面和外墙一圈
  （楼层剖面、电梯、拱门）出现 / 消失本来就合理，不管。离总监 46 米以外（画面外）的不管，替身走出画面就收工。
- **怎么知道**：给每个人的 `visible` 装一个访问器：演出写 `visible` 时记下"演出想要的"并发事件，渲染读到的 = 演出想要的 && 没被通勤藏着。
  不碰演出代码，不每帧比对。`?commute=0` 关掉（对照用）。替身池最多 32 个，满了借离总监最远、不在画面里的那个。
- **验收**：`docs/lab/2026-11-07-3d-pixel/tools/pops.mjs`：总监站在一个地点，模拟 N 秒，记录 30 米内每个人看得见 ↔ 看不见的切换和瞬移，
  区分"和替身交接"、"替身在出入口进出"和"凭空"。2026-11-14：11 个地点各 180 秒，路中间凭空出现 / 消失 0 次、替身不在出入口消失 0 次
  （接管 ≈ 480 次）；改之前每 90 秒几十到一百多次（美食广场最多）。

这是二期"常客真的走进来、走出去"之前的过渡：演出决定人在场景里做什么，通勤只保证他从哪儿来、到哪儿去说得通。

## 三、一个人的数据

### `CastPerson`

| 字段 | 是什么 | 取值 |
| --- | --- | --- |
| `id` | 唯一 id，存档和牵连都引用它 | named 用名字（`rosa`、`hector`）；当天的客人 `guest:<场景>:<槽位>:<天>` |
| `tier` | 哪一层 | `named` / `regular` / `crowd` |
| `role` | 在俱乐部里是什么人 | 会员 `member`、客人 `guest`、孩子 `kid`、家长 `parent`、教练 `coach`、员工 `staff`、摊主 `vendor`、职业球员 `pro` |
| `title` | 身份，一个短词 | "老会员""前台""红土场维护""饮料车摊主" |
| `name` / `nameZh` | 英文名（名字小牌）/ 中文叫法（名册） | "Rosa Ortiz" / "罗莎" |
| `age` | 年纪 | 孩子 6–12、少年 13–17、大人 18–85 |
| `from` | 哪儿人 | 谷地的城镇（Indio、Coachella、La Quinta、Palm Desert……）或外地 |
| `job` | 在外面做什么（员工 = 以前做什么） | "小学校长，退休""UC Riverside 的学生" |
| `member` | 会籍 | 见下 |
| `attrs` | 属性 | 见下 |
| `traits` | 特质，1–3 个 | `traits.ts` 的 id |
| `likes` / `dislikes` | 喜欢 / 不喜欢的东西，各 1–3 样 | "冰柠檬水""红土""吹叶机的声音" |
| `bio` | 故事 | named 2–5 句；生成的人一句 |
| `quirk` | 一个看得见的小习惯 | "打完每一分都要把拍线拨正" |
| `lines` | 按处境的台词，每句 ≤ 16 字 | 处境 = `Activity` + `greet` / `happy` / `upset` / `busy`；不给的用特质和身份的默认 |
| `ties` | 牵连 | 对方 id + 种类 + 一句话（第六节） |
| `week` | 每周来访 | `days`（0 = 周一）+ `hours`；不给 = 每天都在（员工、摊主） |
| `homes` | 在场景里由哪个位置演 | `scene + slot (+ days)`；named / regular 才有，crowd 由选角分配 |
| `look` | 外观 | 见下 |
| `favor0` | 开局对总监的好感 | 0–10，一般 5；老会员对新总监有戒心可以低，老员工可以高 |

### 属性

| 属性 | 取值 | 一期（demo） | 以后 |
| --- | --- | --- | --- |
| `ntrp` 网球水平 | 1.0–7.0，0.5 一档；不打球的人 1.0，会员多在 2.5–4.5，教练 4.5–5.5，职业 ≥ 6.5 | 打一局按和总监（3.5）的水平差算收益；1.0 的人约不了 | 谁和谁打得来（关系、搭档） |
| `fitness` 体能 | 0–100 | 只显示 | 打完累不累、运动狂和老伤的底子 |
| `social` 外向 | 0–100 | 只显示 | 聊天的基础收益；高的人主动打招呼 |
| `patience` 耐心 | 0–100 | 只显示 | 排队、等场能等多久（二期，第四节）；被打扰时的脾气 |
| `spend` 消费力 | 0–100 | 只显示 | 请客、送礼的收益；点贵的、请别人 |
| `loyalty` 忠诚 | 0–100 | 只显示 | 好感回落得多慢；带不带朋友来 |

一期互动的差别全在特质上（第五节）；属性先只在人物卡里画成格子（见过面才显示），二期起一项一项接进行为。每个人只有一两项偏得厉害（Dwarf Fortress 的做法："只说偏离平均的部分"），读得出性子。

### 外观（`CastLook`）

一个人在 45° 俯视、约 20 纹素高的 Q 版人上能被认出来，靠下面这些。named 每人手写，生成的人按种子搭配；同屏的人尽量不撞。

| 部位 | 能表达什么 | 取值 |
| --- | --- | --- |
| `body` + `height` + `stout` | 大人 / 少年 / 孩子；高矮（0.92–1.08）；发福（0.92–1.3） | 老会员可以发福，球员瘦高 |

### 特质（`traits.ts`，26 个）

特质是性子：决定他做什么、怎么回应总监。每条都要在行为或互动里看得见，不做只改一个数的特质。倍率是这个动作的好感变化 × k（负数 = 反感）；"打扰会烦"是他在这些处境下被聊天、请客会扣好感。

| 类 | 特质 | 互动里 | 别的 |
| --- | --- | --- | --- |
| 说话 | 话多 `chatty` | 聊天 ×2、听意见 ×1.5 | 一聊停不下来（多花时间） |
| | 腼腆 `shy` | 聊天 ×0.5、发消息 ×1.5 | 熟了以后最忠心 |
| | 消息灵通 `gossip` | 听意见 ×1.5、聊天 ×1.2 | 听意见会告诉你别人的事（名册多出牵连） |

### 写人物的规矩

- **背景先行**（RimWorld）：先写他从哪儿来、为什么来这座关了十年、刚重新开门的老俱乐部（1994 年办过第一次大赛，2016 年关门），再定属性和特质。
- **有出处的细节**（《八十亿分之一》）：一两件具体的事比一串形容词好记（铁皮饭盒、十九本记分本、线断了两根的拍子）。
- **只亮最突出的**：名册上只显示身份、两个特质、最偏的两项属性。
- **人群要多样**：族裔、年纪、职业、阶层都要散开，**不按族裔分配职业**（2.5D 第一轮评审的问题：拉丁裔人物清一色体力活）。
- 名字和经历都是虚构的；背景地是 Palm Springs / Coachella 谷地（Indian Wells、Palm Desert、La Quinta、Indio、Coachella、Rancho Mirage、Cathedral City）。

## 四、三层人各自怎么活

### named：手写的人

每人一份手写的 `CastPerson`（`cast/named.ts`），有故事、小习惯、自己的台词、牵连和固定的位置（`homes`）。员工每天在自己的岗位上；常客按 `week` 来，不来的日子他的位置是别人。
一期他们由场景里固定的那个人演；二期起按来访模式真的走进来、走出去。

### regular：熟面孔

按模板生成（固定种子，名字和样子每局一样），有名字、属性、特质、一句话背景、每周来访，没有长故事。他们是会员数的脸：名册里大多数行是他们。

- **每周的来访模式**：哪几天、几点到几点、在哪几个场景（`week` + `homes`）。同一个人每周同一时间出现，玩家能记住"周四下午泳池边那个戴渔夫帽的"。
- **短记忆**：最近几次和总监打交道的事（`PersonMem.memory`，名册"最近"）。二期起加上来访的记忆：这一次来有没有被接待、有没有等太久；几次没被接待，好感往下走，还会说出来。
- **不会自己消失。** 好感低只让他冷淡、话少、耐心短；"不来了"只由卡或剧情触发（2.5D 版的教训：自动流失会让新开的几周老会员一下走光）。

### crowd：今天的客人

按 `种子 + 场景 + 槽位 + 天` 生成，属性齐全，一句话背景，没有牵连。不进名册，除非总监和他说过话（见过面的客人进名册的"客人"页签）。
二期起每个客人有**目的、节奏、耐心**：

| 目的 | 去哪 | 一组几人 | 耐心 | 节奏 |
| --- | --- | --- | --- | --- |
| 到达 / 取车 | 停车场 → 大门 | 1–2 | 短 | 跟 clubpark 的落客时间表 |
| 签到 | 前台 | 1 | 中 | 早上 8–10 高峰，下午 3 点回升 |

耐心 = 属性 `patience` 折成分钟，再按特质（急性子短、候鸟长）调。等过了耐心就走：画面上起身、回头看一眼、从来的路走掉（一组人一起走，家长拉着孩子）。
**等待不改经营数**：现在没有模拟；接回以后服务率照模拟算，人群只把"没人服务"演成人。

## 五、互动和取舍

### 两个入口

| 入口 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| **名册**（HUD 右上"名册"按钮，手机上是一张全屏单子；页签：全部 / 会员 / 员工 / 孩子 / 今天在 / 客人，可搜索） | 看：谁、身份、好感格子、今天在不在（在哪儿）；点一行开人物卡：属性、特质、喜好、故事、牵连、最近的记忆；"走过去"（寻路到他今天的位置）；发条消息 | 改变他的东西（除了发消息） |
| **场景里点人** | 总监走过去，冒一行"在想什么"，弹出同一张人物卡（动作按钮在拇指区） | 不在跟前时，要当面的按钮变成"走过去" |

走近了的人头顶有名字小牌（名，没见过面的淡一点）。

**见过面才解开。** 没说过话的人（`met: false`）在名册里标"还没说过话"：名字、身份、肖像、今天在哪儿看得见，属性是"？"，故事、特质的说明、牵连都藏着（"走过去聊几句，就知道他是什么样的人了"）。
总监第一次和他当面打交道（任何当面动作）就解开，也从这时起才能发消息。
名册不是情报面板：认识一个人要走过去。

### 六个动作

按钮和代价在 `cast/actions.ts`（`ACTIONS`、`actionsFor()`），规则在 `cast/state.ts` 的 `act()`；下表是设计意图，数以代码为准。每个动作都要付出点什么（准则 2）。

| 动作 | 当面 | 花多少 | 换来 | 付出 / 风险 | 谁最吃这一套 / 谁不吃 |
| --- | --- | --- | --- | --- | --- |
| **聊几句** `chat` | 要 | 2 分钟（话多的人停不下来：5 分钟） | 好感小涨；第一次就解开名字 | 总监站在这儿（别处的活没人干）；同一天说多了会烦；他正忙会扣 | 话多、心累了、乐天 / 腼腆、讲排场 |
| **请喝一杯** `treat` | 要 | $6 · 5 分钟（孩子是一根冰棍：$3 · 3 分钟） | 好感中涨、心情涨 | 钱；节俭的人不好意思 | 吃货、大方 / 节俭、运动狂 |
| **打一局** `rally` | 要 | 30 分钟 | 好感大涨；记一局（`rallies`） | 最贵的时间：总监半小时不在别处；要他会打球、不在干活；水平差太多他没兴致 | 好胜、运动狂、明星 / 老伤（推掉、扣好感） |
| **听听意见** `ask` | 要 | 6 分钟 | 好感涨；消息灵通的人顺便讲别人的八卦（二期：名册多出一条牵连；完美主义 / 爱抱怨的人说出一处设施的毛病） | 时间；问多了显得没主意 | 老派、好奇、消息灵通 |
| **送个小礼物** `gift` | 要 | $15 · 1 分钟；每人每周一次 | 好感大涨 | 钱最多；送了这周就不能再送；心累了的人不吃 | 讲排场、贪玩的孩子、节俭 |
| **发条消息** `message` | 不要（名册里就能做） | 1 分钟；只对见过面的大人 | 好感涨一点点 | 效果最小；讲排场的人嫌敷衍；同样算"今天说过话" | 腼腆 / 讲排场 |

### 好感、心情、记忆

- **好感**（`favor`，0–10，一位小数）：他对总监的态度。开局 `favor0`，只在互动时变，一期不自己回落。现在好感不碰任何经营数（没有模拟）。
  二期：按 `loyalty` 慢慢回到底子；好感 ≥ 8 他会主动走过来打招呼（冒气泡，不开卡），≤ 2 见到总监扭头。
- **心情**（`mood`，0–100，底子 60）：今天怎么样。好感涨心情跟着涨（打一局再多一点），好感掉心情掉得更多（乐天的人掉一半）；每过一夜往 60 回一半。
  心情是这一次互动的收益系数（0.6 + 心情 / 125：心情 60 ≈ ×1.1，心情 0 只剩 ×0.6）。二期：等太久、没被接待也掉心情。
- **记忆**（`memory`）：每次互动留一行（"第 3 天 · 总监请他喝了冰柠檬水"，带这次的好感变化），只留最近 8 条，人物卡"最近"显示。二期加上来访的记忆（有没有被接待）。

### 规则

收益 = 基础值（聊 0.4、请 0.8、打 1.0、问 0.5、送 1.2、消息 0.2）× 特质倍率 × 下面几条 × 心情系数，好感一位小数。

1. **同一天说多了会烦。** `talksToday` 计今天打过几次交道（每个动作都算，过夜清零）。第二次打六折；聊天、听意见、发消息到第三次起变成扣好感（−0.2、−0.4……，"今天第 3 次了，有点烦"）；
   请客、打一局、送礼不扣，但一次比一次不值（×0.7 一次）。
2. **正在打球、干活时被打扰扣好感。** 他此刻的 `Activity`（按场景里的姿势推断）在特质的 `busyWhen` 里（专注：打球 / 干活 / 健身；急性子：排队；完美主义：干活）→ 好感 −0.5，台词是 `busy`；
   约正在打球的人打一局不算打扰。没有这些特质的人，员工 / 摊主 / 教练在干活、任何人在打球或健身时搭话，收益只剩四成。等他换边歇着、干完活再来。
3. **特质改倍率**（第三节的表）；负倍率 = 反感。早起的人上午 ×1.3、下午 ×0.8，夜猫子反过来；在餐车院子请客 ×1.15。
4. **打一局看水平差。** 总监 NTRP 3.5：差 ≤ 0.5 最过瘾（+1.2）；差 ≤ 1 还行（+0.7）；他强太多没意思（−0.2，爱带人的除外：教得开心）；
   他弱太多被虐（−0.3，孩子除外：陪孩子打球很开心）。老伤的人推掉（−0.3，只花 2 分钟）；不打网球的人（NTRP 1.0）约不了。
5. **身份改能不能做。** 孩子请客是一根冰棍（$3）；不给孩子发消息；发消息要先当面说过话（见过面才有联系方式）。
6. **钱不够就做不了；礼物一人一周一次。** demo 里总监有一笔零用钱（开局 $120，`CastState.money`），只用来请客、送礼；不是俱乐部的账。
7. **结果当场演出来**：他说一句（气泡），卡片下面一行写清楚为什么（"好感 +0.8 · 吃货：很吃这一套""好感 −0.5 · 专注：打球的时候被打扰了"）；做完推 demo 时钟（动作花的分钟）。

## 九、待定问题

1. **名册的去留和形态（准则 1）。** demo 允许一个看信息的菜单。接回游戏时：留成"总监的小本子"（只读，HUD 上一个按钮）、只在点人时出小卡、还是干脆不要？"走过去"算不算菜单操作？
2. **员工是不是 named。** 场景里的代客、教练、裁判、球童、摊主现在都是有名有姓的人，但"员工要不要有、怎么干活"归 M-0。员工的好感以后管什么（干活的快慢？会不会走？）跟着 M-0 定。
3. **常客等不到人自己动手**（2.5D 版 Ortega 夫妇的旧钥匙）：等烦了自己开门、自己拿毛巾，算不算没服务到？建议不算缺口、不产生收入，只写进他的记忆、好感往下走。
4. **好感碰不碰经营数。** 建议照 2.5D 版的边界：好感只影响耐心、带不带朋友来、卡；碰钱、会员、声望的例外逐条列在本文，再加要先改这里。
5. **生成的人能不能"升格"。** 见过面、聊得来的客人，以后会不会变成常客（有名字、每周来）？会的话名单就不是固定的，存档要记他。
6. **总监的零用钱和时间。** demo 里请客、送礼花的是总监自己的钱，互动花的游戏分钟只推 demo 时钟。接回以后：花俱乐部的钱还是总监的？一天多长、聊一次值多少游戏分钟（M-0「一局和一天的结构」）？
7. **人数。** 全俱乐部约 240 个位置，named 71、regular 102，名册 173 行，人群补满。手机上名册多长还看得过来、要不要按场景分页，试玩再定。

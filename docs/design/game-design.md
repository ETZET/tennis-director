## 玩法准则（Tenets）

2026-10-31 定，冲突时前面的优先（和 `CLAUDE.md` 同一份，原文照录）。2026-11-09 删掉原准则 5（"日常经营靠招人和排人"，归档在
[`tenet-5-staffing.md`](../archive/pre-3d/tenet-5-staffing.md)），原准则 6 改号成 5；之前写的 ADR、契约和代码注释里的"准则 6"就是现在的准则 5。

1. **不做菜单式操作。** 玩家的动作要么回应事件（卡、来找你的人），要么直接点场景或 HUD 里的东西。不加"面板 → 子菜单 → 按钮"式的管理操作。
2. **选择要有取舍。** 每个选项都换来一些、付出一些（钱、时间、总监位置、好感、以后的风险）；不能有各方面都更好的选项。
3. **不同的选择通向不同的后果。** 选择要留下痕迹（后续卡、人物态度、设施、结局），并能在因果日志里看到。
4. **事件是偶发的，而且有分量。** 卡不是流水线：隔一阵才来一张，每张都配足够的界面（谁来找你、现在的处境、每个选项的代价和后果），让选择显得重要。
5. **不操作时世界照样运转，局面慢慢回到"你布置的样子"。** 有人守的地方维持住，没人管的设施按使用量慢慢变旧（先出画面信号，再掉档）；收入和满意度只在有人在岗时产生，没人就是零、不倒扣；钱、会员、声望不实时漂移，每天收盘按今天的服务率结算一次（结算卡讲清楚为什么，ADR 0024），今天没有客人就不动。

在 3D 里怎么读：准则 1 = 走过去、点场景里的东西、按住干活，没有菜单；准则 2 = 总监同一时刻只在一处，去哪儿就是取舍；
准则 5 = 场景里没人管的地方先出画面信号（沙、叶子、空水桶、排长的队），再到数字。

## 概述

你是 **Palm Oasis 网球俱乐部**（加州 Indian Wells，科切拉谷的沙漠里）的总监。俱乐部有大门和代客泊车、露天前台、匹克球场、两片红土、
会员场和青训场、中心球场、棕榈喷泉广场、会所和泳池；四周是棕榈泉那样光秃、一层层的岩山，车从东边山口开进来（不是浮空岛，ADR 0027 修订 0005）。

一句话：**你在俱乐部里走来走去，走到哪儿哪儿就好起来；你不在的地方，慢慢乱。**

- **总监是步行的。** 玩家直接操控他（ADR 0029）：走、拿工具、按住干活。俱乐部是活的：会员排队签到、双打一分一分地打、孩子在池边玩水、
  代客把车开去停；这些人会因为总监在不在、做没做而变。
- **总监一个人顾不过来。** 在前台签到就没法去红土场拖场；有没有别人帮手、怎么帮，在重新设计里定【待定】。
- **画面就是反馈。** 拖过的红土变平、扫过的线变白、捞干净的池水变亮、排短的队伍——结果先在场景里看到，收盘时再到数字里（准则 5）。
- **美术方向：** three.js 3D 像素（t3ssel8r 风格），午后金光配色（方案 6 golden），每纹素 1 个 CSS 像素；见 [architecture.md](architecture.md)。

## 核心循环

### 几秒到几分钟：总监在场上【场景】

看见 → 走过去 → 干活 → 有人反应 → 留下痕迹。

1. **看见。** 信号都在场景里：头顶气泡（"代客呢？""没水了…""排好长…"）、地上的沙和叶子、空了的水桶、松掉的网、顶栏的几格状态。
2. **走过去。** 拖动走或点地面寻路；走近一样东西才出按钮（动作键、拿/放键），点场景里的东西会自动走到站位。
3. **干活。** 一次性的活按一下（签到、递钥匙、换水桶，几秒）；持续的活按住（拖场、扫线、浇水、捞叶子、摇网），可以边干边走的就边走；
   工具拿在手里带着走（拖垫、扫线刷、水管、捞网、扫帚、水壶、捡球器、钥匙、毛巾、球包车）。
4. **有人反应。** NPC 读总监的位置和做完的事：会员签完到拿毛巾走、代客腾出手接下一辆车、绷好网的场开放、拍架上等着的人上场、长椅上的人坐回来、鸟飞回来。
5. **留下痕迹。** 场面、水位、队伍长度、谁手里拿着什么都是场景状态；接回游戏以后由模拟结算（ADR 0029 第 7 条）。

**取舍就是总监站在哪儿。** 每个场景都设计成"他在这儿，那儿就没人"：在远场拖红土时近场的水站没人换；在前台签到时门口的沙没人扫；
在落客点接钥匙会员不用干等，可钥匙得送回岗亭，后面的车要排队。

### 一天【模拟】

营业 8:00–20:00，需求按时段来（早上租场、下午上课、傍晚成人班）。
20:00 收盘按今天的服务率结算钱、会员和声望，停下来弹一张结算卡（ADR 0024，见下文"每日结算"）。一天以上（一周、一局）怎么走，在重新设计里定。

**要重新设计的（开放问题，[backlog.md](backlog.md) 的 M-0）：**

1. **一局和一天的结构：** 一次打开游戏玩多久、一天在真实时间里多长；场景是实时秒，模拟是游戏分钟，一件活、走一趟各算多少游戏分钟。
2. **目标和推进：** 有没有星级、等级、解锁；俱乐部怎么"变好"，变好在场景里长什么样；地图要不要长。
3. **玩家在追求什么：** 一局有没有终点（期限、打分、赛事、无尽），赢和输是什么。
4. **员工要不要有：** 要的话怎么来、怎么让他们干活（不再是拖头像派岗位）；场景里的代客、教练、裁判、球童是氛围还是可以招的人；原来的岗位和工单留不留。
5. **事件和卡：** 还要不要卡；建议"卡以人的形式来找你"（有人走到总监跟前冒气泡，点他开卡），选项把总监叫走（errand）改成总监自己走过去。
6. **结算怎么接上场景：** 收盘那张卡上的每一行在场景里看得到原因（前台的队伍、红土的场面、喷泉的叶子）；服务率在没有派工以后按什么算。
7. **失败状态：** 有没有破产、会员走光、设施停用；没人管的地方慢慢乱到什么程度为止（准则 5）。

### 已经定下的（2026-11-08 这一轮）

- 配色：默认方案 6 午后金光（`golden`），右上角可切；像素默认 1×（每纹素 1 CSS 像素），左上角可切 1 / 1.5 / 2 / 3。
- 不是浮空岛：地面铺出画面，地图边是低成本的山（不贴岩层），最高的山在西北，车道翻山口出地图（`boundary.md`）。
- 各场景共用一套世界坐标（`clubsite/world.ts`）。
- 红土场：两片场之间只一道围网，贴南墙的场不拉南围网，东步道接到南墙。
- 匹克球场：东北开一道员工小门（去前台拿备用水桶）。
- 喷泉广场：蒲葵四棵，围成朝南开口的马蹄形。
- 中心球场：自己的场地颜色；裁判椅不带遮阳顶（不挡裁判）；有球童。
- 青训场：西场是教练带孩子，东场是发球机（和 2.5D 游戏反过来）。
- 会员场：遮阳帆下有喷雾，场边会积水洼，总监用刮水板刮。
- 饱和度靠主角材质的彩度拉上去（目标 ≥ 0.42），不靠后期；参考图永远不进仓库（`refcheck.mjs`）。

## 模拟里已经有的【模拟】

下面是 `packages/sim` 现在真的在算的、和归档的主线无关的东西，一条一行，细节和数值看后面列的文件。它们是 2.5D 时期按 Palm Oasis 地图设计的，接回 3D 场景时要逐条对一遍。
主线和派工那几条（修复解锁、掉档、招人、星级、选路、赛事、地块、结局）模拟照旧在跑，列在 [main-line-2.5d.md](../archive/pre-3d/main-line-2.5d.md)。

- **时间、季节、天气：** 营业 8–20 点，夜里跳过；秋（第 1 天）、冬（第 36 天）、春 · 风季（第 71 天）；晴 / 阴 / 雨 / 大风 / 酷热。雨天户外场没有场地收入。
- **岗位和工单：** 派工模型（已归档）的数据结构，模拟照旧在用：每日结算的服务率、场地可用度的打扫都按它算。留不留在重新设计里定。
- **走路：** 按导航图走最短路，地点之间 5–86 游戏分钟；分钟数是从 2.5D 地图的步道量的，3D 场景的世界坐标还没对过（接回时重建检查）。
- **衰减：** 没人维护的设施每天掉状况，有人守的掉得慢（准则 5）。
- **场地可用度（ADR 0022）：** 五处球场各有积沙、积水、球和垃圾、线褪色、裂缝五种短期脏乱，玩家只看到"能打 / 勉强 / 不能打"三档；员工打扫工单、维护岗位、总监亲手扫都能清。契约 [court-care-contract.md](court-care-contract.md)。
  3D 场景里的吹沙、拖场、扫线、浇水、刮水，正好是这五种脏乱的画面版。
- **每日结算（ADR 0024）：** 见下一节。
- **事件卡和导演：** 里程碑、阈值、日历、后果、随机五种来源；倒计时到了按默认处理；导演按压力值调节奏；停滞卡一周最多一张。有的选项把总监叫走一段时间（errand）。现有的 27 张卡都是为归档的主线写的。
- **因果日志：** "因为……所以……"的账本：谁在哪干了几圈、哪张卡引出了哪张卡、今天的钱为什么变。

### 每日结算（ADR 0024）

每天 20:00 收盘，钱、会员、声望都只按**今天**算一次，写一条因果日志、一条快讯，弹一张结算卡（不管几倍速都停）。
今天一整天没有一个开着的有需求岗位（开局、雨天全关），声望、会员都不动（准则 5：没人就是零、不倒扣）。
卡上讲：今天的钱按来源拆开、声望和会员各自为什么变、服务率和缺人最多的岗位、不能打的场、走掉的会员、今天的人、明天（天气、可能变脏的场、赛事和招聘日）。
公式和字段见 [daily-settlement-contract.md](daily-settlement-contract.md)；`apps/game/src/settle.ts` 是卡。

接回 3D 以后，"今天的服务率"要能从场景里看出来：前台签到的队伍、红土场的场面、喷泉的叶子，都是收盘那张卡上的一行；没有派工以后服务率按什么算【待定】（M-0 第 6 条）。

### 经济的几个数【模拟】

开局现金 $3000、声望 5、质量 10、会员 0。收入来自岗位每圈（基数 × 能力系数 × 会员或声望系数）、会员会费（每人每周 $12，按天折算）、卡和赛事；
支出是工资、设施维护费、工单材料。平衡报告 `docs/balance/indian-wells.md`，改了平衡数值要重跑（CLAUDE.md）。

## 平台

手机优先：界面先按 390×844 竖屏设计，操作在拇指区，点击目标至少 44 px，拖动和点按（Pointer Events），不依赖悬停和键盘。
每个场景竖屏、横屏都有取景（竖屏看一竖条主角，横屏看全）；桌面加键盘（WASD / 方向键、空格 / E、F / 回车）是第二布局。截图和试玩评审以手机画面为准。

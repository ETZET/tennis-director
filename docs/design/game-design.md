## 概述

玩家扮演网球总监，接手一座废弃了十年的网球俱乐部：加州沙漠里的 Palm Oasis 网球俱乐部（位于 Indian Wells, CA；ADR 0018）。整局游戏都在这一张地图上，没有换场景、没有分幕。画面是 2.5D 等距像素、上帝视角（ADR 0019）。时间持续流动，不是回合制。

一句话定位：**经营一个网球俱乐部的日常，看它从废墟里活过来。**

玩家应该感到的是**复原**：看着一片废墟被自己招来的人一处一处修回来、重新热闹起来。

- **进度靠经营。** 招人、把人放到该在的岗位上，设施一处处修好，俱乐部一点点活过来。事件卡是偶发的点缀。
- **人手最稀缺。** 总监也是一个劳动力，派到哪里就只在哪里。开局只有总监和 Dale 两个人。
- **修好就是解锁。** 每修好一处设施，就开出新的岗位和下一步的修复，画面也随之复原。
- **美术就是反馈。** 修好的地方在画面上真的变回来；有人在岗位上干活，就有活动动画演出来。
- **（提议）往前走不只靠修。** 俱乐部星级是看得见的主轴；赛事阶梯填中段；员工的成长开出新玩法；结局两套方案待定。见"推进结构"。

**平台：手机优先。** 界面先按 390×844 竖屏设计：大拇指能碰到的地方放操作，点击目标至少 44 像素，用拖动和点按，不依赖鼠标悬停和键盘；桌面是第二布局。试玩评审以手机画面为准。

## 玩法准则（Tenets）

2026-10-31 定。所有玩法改动和评审都对照这六条；互相冲突时，排在前面的优先。

1. **不做菜单式操作。** 玩家的每个动作，要么是对事件的回应（事件卡），要么是直接和场景或界面里的东西互动（点地点牌、拖人、点 HUD 上的提示）。不加"打开面板 → 选子菜单 → 按按钮"的管理操作。数据可以放在 HUD 和状态条里给玩家看，但改变局面的动作不从菜单发起。检验：一个新功能的第一反应如果是"加个按钮或面板"，先想它能不能是一张卡，或者点场景里的某样东西。
2. **选择要有取舍。** 每个选项都换来一些东西，也付出一些东西：钱、时间、谁站在哪儿、某个人的好感、以后的风险。不存在各方面都更好的选项。检验：机器人报告里没有被压制的选项；同一张卡，不同的玩家都有理由选不同的项。
3. **不同的选择通向不同的后果。** 选择要留下痕迹：后续事件、人物态度、设施状态、结局。玩家事后能在"因为……所以……"里看到自己的选择在哪里起了作用。检验：同一个种子换一种打法，故事和结局明显不同；每个结局都有一条走得到的路。
4. **事件是偶发的，每一张都有分量。** 事件卡不多，来的时候要配足够的界面，让选择有意义：谁来找你、此刻的局面、每个选项会动哪些东西、之后可能怎样。检验：一个游戏日里大多数时间没有卡；每张卡打开时，玩家不用翻别处就能看懂这个选择的分量。
5. **日常经营靠招人和放人。** 让俱乐部变好的主要手段，是玩家主动把人（包括总监）拖到场景里的岗位和工单上，而不是等卡来。这些动作同样要有取舍（准则 2），也同样不走菜单（准则 1）。检验：一局里玩家主动发起的动作多于回应卡片的次数。
6. **玩家不操作时，世界照样运转，局面慢慢回到"你布置的样子"。** 有人守的地方维持住，没人管的设施慢慢变旧；变化先在画面上看到，再反映到数字上。收入只在有人在岗时产生，没人就是零，不倒扣；会员数、声望等存量不实时漂移，每周日按一周的平均状况结算。检验：放一天，数字几乎不动；放一周，没人管的场掉一档。

## 核心循环

### 四个时间尺度

| 尺度 | 玩家在做什么 |
| --- | --- |
| 几秒 | 看到需求（地点牌上红色的空位、工单）→ 把人拖过去 → 看进度 → 出收益。每次拖动都有机会成本：走过去要时间，拉走持续岗位丢掉这一圈。 |
| 一天 | 需求按时段来（早上租场、下午上课、傍晚成人班），人手比岗位少，玩家一天重派两三次人。排班就在拖动里，没有排班表。 |
| 一周 | 周日收盘按本周服务率结算会员和声望；没人管的设施按天变旧；修复工单一张张做完，开出新的地方；每两周一个招聘日。 |
| 一局 | 16 周（112 天）：从扫出第一块场地，到修好中心球场、办成表演赛。 |

张力：会员越多、开的地方越多，需求越大，人手就不够；招人要付工资；钱还要拿去买修复的材料。成功本身带来新的问题。

### 人

详见 [people.md](people.md)（研究、四类作用、特质、招聘日怎么出人、以后）。

- **作用（四类）：** 教练（上课、学院，招来接任主教练）、维护工（修和维护设施）、特殊岗位（穿线师、体能师、球童、前台……
  带着一门手艺，打开只有他能干的岗位）、球员（练球、出去打比赛，赢了带回奖金和名气）。普通岗位谁都能干，只有特殊岗位和球员的岗位限人。
- **能力（0–100）：** 教学、维护、服务，球员另有球技。能力决定干活速度（能力 50 的人是 1 倍，`0.5 + 能力/100`）和岗位收入。
- **一句话背景 + 1–2 个特质：** 背景说明他从哪儿来、为什么来这里；特质是数值的摘要，大多带代价或条件
  （"完美主义"维护 +12、服务 −10；"沙漠长大"大风天和风季维护 +15；"夜猫子"16 点后各项 +12；"退役名将"表演赛 +5%）。
- **工资**按天折算记账、每周日在周结算里讲一次；特质的声望（`star`）每天攒、周日结算；**士气**只属于员工（`burnt_out` 士气慢慢掉、`eager` 慢慢涨；士气暂时还不影响干活，见 people.md「以后」）。
- **总监**是一个没有情绪的劳动力：没有士气、不要工资。每干完一圈岗位或一张工单，对应那项能力 +0.3，上限 80；跨过整十时快讯会报一次。
- **主教练：**开局是 Dale。招来的教练接任主教练，Dale 留下当员工；如果接任的人走了，Dale 接回来。
- **走路：**重派一个人，他要按步道走过去，到了才开始干。步道绕，地点之间走 5–86 分钟（游戏时间）。

### 岗位和工单（ADR 0012）

- **持续岗位**是地点上的一个"位子"：有人坐上、在它的时段里，一圈一圈地转（一圈 1 小时），每圈结算一次收益。有时段的岗位是"需求"：时段里没人，计入服务率的分母。
  - 被玩家或事件**中途拉走**，这一圈作废，已算的服务分钟退回去，快讯会说"这一圈白干了"。
  - **维护岗位**没有时段，随时可以干，每圈把设施状况往回拉（`4 × 速度`）。
- **工单**是长在问题上的一次性任务：扫沙、换网、修会所。拖人上去就开始干，可以几个人一起（每张有人数上限），拉走进度保留；第一个人到场时扣材料费，钱不够开不了工。
  - **修复工单**只做一次（`once`），做完设施换状态。还没开出来的修复，在地点清单最后显示一行灰的预告，说明要先修好什么（ADR 0015）。
  - **清理工单**在设施状况跌破 40 时冒出来，做完状况回升。
- **习惯（ADR 0014）：**玩家亲手派过的岗位会被记住（每人最多 4 个，时段不重叠）。岗位关门、工单做完或闲着时，这个人自己走去下一个记住的班；在做工单的人，班一开始就去上班，下了班回来接着做。
- **地点牌（ADR 0013）：**一个地点一块牌，牌上是此刻要人的岗位（空着是红色 +，有人是头像加环形进度）和工单数。点牌打开拇指区的地点清单；拿着人点它（或拖上去松手），只有一项能接的活就直接派。

### 衰减（准则 6）

- 每个"能用"的设施状态有 `decay_day`：没人维护时每天掉这么多状况（会员场和红土场 5、青训场 4、泳池 3 ……）。岗位每圈还有一点磨损。
- 季节倍数：秋 1，冬 0.8，春（风季）1.3。
- 状况低于 30，这处设施对质量的贡献减半，到 0 归零；地点牌上出现红色"!状况"，快讯提醒一次。还废着的设施不会再变旧，也不挂提醒。
- **掉档（ADR 0017）：**周日收盘时状况低于 15，设施掉一档（会员场新铺面 → 能打 → 停用；其他设施 开放 → 停用）。停用的设施没有场地、岗位不开，冒出一张"重开"工单（$30–450、2–8 小时），做完回到原来那档。周六收盘对"明天就要掉"的再提醒一次。修复主线不倒退：停用的设施照样算后面设施的前提。

### 画面

- **画法：** 2.5D 等距像素，Canvas 2D 软件光栅，不用 WebGL（ADR 0019，接口契约见 [iso-architecture.md](iso-architecture.md)）。不投阴影，静止时只停在 4 个等距角。
- **光：** 天空、山脊和一天的光（早晨、白天、黄昏、夜里）跟游戏时钟走；灯头、窗户、串灯夜里亮。
- **人：** 人物是约 8×14 像素的精灵，运行时换色。
- **素材：** 一律是文本字符画，不放图片。
- **设施：** 每个"设施 · 状态"一层画面层。开局的积沙、倒网、碎石是一层，修好以后换上新场地、新网、有水的喷泉和泳池、补好的看台。状况往下掉时，先在画面上长出沙堆和杂草（`wear`），再掉档。
- **还没做完的精细化：** 见 `backlog.md` 的美术轨道和 [../art/](../art/README.md)。

## 一局的节奏

| 时间 | 一般会发生什么 |
| --- | --- |
| 第 1 天 | Dale 带你看仓库里的发球机（留着还是卖掉）。两个人去扫会员场、换网：十年来第一块能打的场地。 |
| 第 1–2 周 | 会员场有人租场、下午上课，第一批客人来了；攒钱修红土场、青训场或会所。 |
| 会所修好 | 第一个招聘日。之后每两周一个，一共四个。 |
| 第 4–8 周 | 棕榈喷泉、匹克球场。人多了，总监从"干活的人"变成"把人排好的人"。 |
| 第 13 周（第 85 天） | 投资方来看进度：亲自带他们转（总监离开 3 小时，声望按修好了几处加），还是让他们自己看。 |
| 第 9–15 周 | 泳池、中心球场：最贵的两处，要五六个人干好几天。 |
| 第 112 天 18 点 | 期限：还没办成表演赛，就结束。 |

参考：会招人、排得满的贪心型机器人一般第 91–111 天办成表演赛（`docs/balance/indian-wells.md`）。真人玩家会慢一些，期限是否要放宽等真人试玩后再定。

时间换算：营业 8:00–20:00，1× 下一个营业日约 2 分钟真实时间；所有有需求的岗位都有人、又没有工单在做时加速。一局按 1× 约 3–4 小时。

## 胜负

- **通关：**在重建好的中心球场办成表演赛。表演赛是一张工单（8h · $3000 · 最多 6 人，声望 50 以上才出现），带判定：
  成功率 = `clamp(0.3 + (声望 − 50)/80 + (质量 − 60)/100 + Dale 当裁判 0.05 + 招到退役名将 0.05, 15%, 85%)`。
  成功：+$6000，结局"表演赛办成了"。冷场：只回来 $800、声望 −6，一周后可以再办。
- **失败：**第 112 天 18 点期限到了（结局"期限到了"）；或者每天收盘时现金低于 −$2000（结局"钱花光了"）。

**v0.4 提议：**期限要不要判输、表演赛之后怎样，见"推进结构 · 结局"的两套方案。

## 推进结构（v0.4 提议，ADR 0020）

**这一节还没有做进游戏。** 它回答三个已经测出来的问题，参考开罗游戏的推进方法（[research-kairosoft.md](research-kairosoft.md)）。数值都是初值，要用普通玩家机器人（novice、average、good）校准。

### 为什么要改

| 测出来的问题 | 证据 | 根因 |
| --- | --- | --- |
| 中段没事做 | GM-1：老手第 52–84 天一张卡都没有，只剩攒钱 | 只有一条修复链，链上的下一环太贵时，玩家只能等钱 |
| 输在最后一步 | E2：16 周的败局里，复原 7/8 或 8/8 占大多数；期限每差一周，average 的通关率变 20–35 个百分点 | 唯一的目标在终点，唯一的判定是硬期限 |
| 后期空心 | 声望后期顶到 100；修完中心球场以后钱没处花 | 一条进度轴（复原 x/8），后期没有新机制 |

开罗的做法是：一条看得见的等级主轴；五种不同的钥匙；在固定的日历节拍上轮流给玩家新东西；结局是软的。我们照这个思路改，但守住准则 1（不加菜单）和准则 4（卡是偶发的）。

### 星级：一条看得见的主轴

俱乐部有 0–5 星，挂在大门的牌子上，也显示在 HUD 状态条上，替代现在的"复原 x/8"。每一星是一张复合清单：

- 修复只是其中一条；
- 门槛尽量用已经在发生的事（会员、声望、修好几处）；
- 新加的只有赛事一类要求：★2 的内赛、★3 的奖杯、★4 的邀请赛。

| 星级 | 名字 | 要求（全部满足） | 升上来开出什么新机制 |
| --- | --- | --- | --- |
| ★0 | 废墟 | 开局 | — |
| ★1 | 能打球了 | 会员场能打；会员 ≥ 5 | 月度内赛（主办赛事） |
| ★2 | 会所开张 | 会所开张；修好 3 处；会员 ≥ 20；办成过 1 次内赛 | 地区赛（外出赛事）。招聘日仍挂在会所开张上，不往后推：不招人修不完，晚一周招人代价太大 |
| ★3 | 社区俱乐部 | 修好 5 处；会员 ≥ 45；声望 ≥ 30；奖杯 ≥ 2 | 邀请赛（大型主办赛事）；赞助位（银行横幅改成按周付钱的赞助） |
| ★4 | 度假名园 | 修好 7 处；会员 ≥ 70；声望 ≥ 50；办成过 1 次邀请赛（第 12 周起，奖杯 ≥ 4 也算） | 表演赛的筹备（改成要 ★4 + 中心球场重建，替代现在的"声望 ≥ 50"） |
| ★5 | 沙漠名园 | 在中心球场办成表演赛 | 结局（见下文"结局"） |

- **每一星开一个新机制，而不只是新建筑。** 开罗的后期几乎都垮在"只剩更大的数字"上，这条是专门防这个的。
- **升星是一个时刻，不是一张卡。** 镜头转到大门，牌子换成新的星，快讯用周结算的写法列出开了什么。升星不暂停，也不占卡的名额（准则 4）。
- **门槛随时间放宽（橡皮筋）。** 第 12 周起，★3、★4 的会员和声望要求降两成；★4 的"办成过邀请赛"也可以用"奖杯 ≥ 4"代替，错过或被雨搅了邀请赛不会把表演赛锁死。打得好的人早拿到，打得差的人晚点也拿得到，减少"最后一步输掉"。
- **"奖杯"** = 办成一次主办赛事，或者在外出赛事里赢下来。
- **赞助续约不用操作。** 收下横幅以后，赞助在周结算里按周付钱；每四周的周日看一次条件（声望 ≥ 30、这四周办过或赢过一次赛事），满足就续，不满足就走，快讯讲原因。不加卡（准则 4），也不加按钮（准则 1）。

### 赛事阶梯：中段的节奏器

网球天然有赛事日历。赛事是中段最主要的短期目标：

- 每一项都有固定的日期、报名费、奖励和附加目标；
- 参赛条件规定了你要什么样的人。

**赛事不是卡：**

- **主办赛事**提前一周作为工单出现在那一处的地点牌上，到日子开出临时岗位，玩家把人拖上去，就算参加（准则 1、5）。
- **外出赛事**沿用现在大门的"出去打一站比赛"工单。
- **不参加没有惩罚**，只是拿不到奖励。

| 赛事 | 主办 / 外出 | 日期（初值） | 条件 | 报名费 | 怎么打 | 附加目标 | 奖励（初值） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 月度内赛 | 主办 · 会员场或红土场 | 第 3、7、11、15 周的周六 9–17 | ★1；至少 2 块能打的场地 | 材料 $60 | 当天开"签到"（服务）和"裁判"（教学）两个临时岗位 | 当天服务率 ≥ 80%；到场会员 ≥ 10 | 声望 +2，会员 +2；奖杯 1 |
| 地区业余赛 | 外出 · 大门 | 第 5、9、13 周 | ★2；有球员 | $200 | 球员离开 6 小时，和现在的"出去打一站比赛"一样走大门 | 一次判定，成功率看球技（同 `pl_tournament` 的公式） | 赢 +$800、声望 +5；赢了算奖杯。现在每 6 天一次的"出去打一站比赛"保留，当作小比赛，不算奖杯 |

**取舍都在已有的循环里：**

- 赛事要从修复和日常岗位上抽人；
- 报名费和修复材料抢同一笔钱；
- 外出赛事让球员离开练球；
- 邀请赛一旦接下，当天下雨就白花报名费。

**目标覆盖：**

- 第 7–13 周每周至少有一个赛事节拍，直接填上 GM-1 测出的空档；
- 卡的总数不用往上加（"需要拍板的事" E7-1）。

### 五种钥匙

现在只有一种钥匙：修好设施。提议加到五种，让"往前走"不只有攒钱一条路。

| 钥匙 | 开出什么 | 现状 |
| --- | --- | --- |
| 设施 | 修好一处，开出岗位和下一步修复（ADR 0015） | 已有 |
| 星级 | 每一星开一个新机制（见上表） | 新 |
| 赛事 | 赢下或办成一级，开下一级；奖杯算星级 | 新 |

- 招聘卡上会多显示一行"潜力"，招人的取舍也就多了一层：现在便宜，还是以后有用。

### 结局：两套方案，待拍板

两套都保留"现金低于 −$2000 就破产"这一条。做法是：两套都做进模拟，用地图配置 `ending_mode` 切换，先用机器人对比，再由真人试玩决定（人-10）。

**方案 A：期限是结算点，不判输**（开罗的做法）

- 第 112 天 18 点结算打分，打完以后可以接着经营；之后不再有期限，也不再出新卡。
- 提前办成表演赛就到 ★5。这时来一张结局卡：马上结算（提前的天数加分），或者接着经营到第 112 天再结算。
- 分数在结局卡上逐项列出，相当于星级清单在终局又用一次：

| 项 | 分 |
| --- | --- |
| 星级 | 每星 1000 |
| 奖杯 | 每座 300 |
| 会员 | 每人 10 |
| 声望 | 每点 10 |
| 办成表演赛 | 2000，每提前一天再加 50 |
| 现金 | 每 $10 一分 |

- 评语按分数分 S、A、B、C、D 五档。
- 可选：下一局可以带一样东西进来，比如总监的能力（打折），或一位老班底。这接上了最早"用心栽培的人要保留"的想法，但存档和平衡都要另算，先不做。

**方案 B：保留硬期限，分档并加橡皮筋**

- 开局选期限：20、16、15 周（E2 的建议）。
- 期限前最后两周，中心球场重建的材料费 −20%（三档都是最后两周）。依据是 E2 测出钱是最陡的杠杆：全部材料费 ×0.9 时，average 的通关率从 54% 升到 72%。只给最后一笔打折的效果还要重跑。
- 表演赛仍然是唯一的通关条件。

| | 方案 A：结算打分 | 方案 B：硬期限分档 |
| --- | --- | --- |
| 解决"输在最后一步" | 直接解决：差一点也是 B 或 C，不是"输" | 部分解决：橡皮筋和低难度档减少这种局 |
| 张力 | 风险：Hollow Creek 的评审发现"目标太开放，张力就没了"。A 保留期限当打分时刻来缓解，但没有"输"可能让后期松掉 | 保留现在的张力和冲刺感 |
| 重玩价值 | 高分和更早办成表演赛就是重玩的理由 | 靠难度档 |
| 工作量 | 结局卡、打分、续局；带东西进下一局最费事（先不做） | 开局选档、期限可配置（LG-6 已有） |
| 风险 | 张力要靠真人试玩确认 | E2 的数据基于旧版本，要重跑 |

我倾向 A：它直接对着 E2 测出的问题，也是开罗研究里最重的一条结论。但 A 的风险是张力，这只有真人试玩能判断。所以建议两套都做进模拟，交给人-1 的试玩来定。

- 普通玩家机器人：average 在第 7–13 周每周至少碰到一个赛事节拍；第 52–84 天"既没有卡也没有赛事"的空档 ≤ 7 天。

## 经济

- **开局：**现金 $3000，声望 5，质量 10，会员 0。
- **收入：**
  - 岗位每圈：基数 × `(0.6 + 能力/100)`，再乘会员或声望系数。基数大致是：看场 3–6、上课 8–12、棕榈喷泉 7–8、匹克球联赛 14、泳池小木屋服务 22、水中健身课 12。
  - 会员会费：每人每周 $12，按天折算。
  - 两张卡：卖发球机 +$400，银行横幅 +$2500。
- **支出：**
  - 工资（Dale $150/周，候选人 $140–900/周）。
  - 设施维护费（修好以后每周 $15–300）。
  - 修复材料费，全部修完加上表演赛约 $28,000。
- **会员：**每周日结算一次，`修好的场地数 × 服务率 + 有需求 × ((质量 − 30)/12 + 声望/30)`。有上限：每块修好的场地撑得起 12 个会员（按修好的算，下雨天关门不减上限），会所开了再多 15 个；超出的人周末就不续了。岗位每圈也有小概率带来一个会员。
- **声望：**每周日 `有需求 × ((服务率 − 0.5) × 2 + (质量 − 50)/25) + 修好的设施数 × 0.15 + 员工特质`，加上修复、卡和部分岗位的零头。0.5 是服务率的及格线。
- **服务率和"有需求"：**服务率 = 本周有需求的岗位分钟里有人在岗的比例。一周里没有一个开放的岗位（没有需求）时，服务率无从谈起：显示"—"，算 0，"有需求"为 0，声望和会员的服务项、质量项都不算（准则 6：没人来就没有口碑，不倒扣）。
- **周结算（GM-1）：**每周日收盘写一条因果日志、发一条快讯：服务率和及格线、缺人最多的岗位、这一周的钱（工资、维护、会费、设施收入）、声望各项、会员上限、质量这周走了多少和它在向哪个目标靠近（目标各项）。现金仍按天折算记账，但不每天各写一条。
- **质量：**每 10 分钟向目标靠近。目标 = `10 + 设施质量 + 开着的场地 × 2 + 服务率(%) × 0.2 + 主教练教学 × 0.15 × 专注度 (+ 发球机 4)`，内容里拆成几项写（`rules.quality_target`），周结算按项讲。

### 引擎

- **四种来源：**里程碑（固定剧情）、阈值（状态满足条件）、日历（固定日期，可以预见）、后果（选项安排的后续卡）。另有随机卡（喜剧和小危机）。
- **倒计时：**卡不处理就过期，执行默认后果（参考 Cultist Simulator、Frostpunk）。重要的卡打开时自动暂停。
- **导演：**每隔一段时间看压力值（现金、未处理的卡、质量），压力高时多发好消息，太平稳时扔一个危机（参考 Left 4 Dead 的 AI Director 和 RimWorld 的叙事者）。一张卡打开后至少隔 4 小时才抽下一张；随机卡一局最多出现 2 次（起风了是 4 次）。
- **停滞时（e7）：**几张"停滞卡"只在 `quiet_days ≥ 7`（一周没来过任何卡）时才能被抽到，每张只来一次；来了以后 `quiet_days` 清零，所以最密也是一周一张，不会变成流水线。有人连续闲着（`idle_days`）时 Dale 会来找你，给出下一步的两个做法。
- **轻提示（e7）：**有人闲着时，员工条上直接写出"下一步"能开工的活（修复优先、便宜的优先），那一处地点牌的工单格亮成琥珀色；拿起人以后由落点高亮接手。不加面板（准则 1）。
- **因果日志：**状态条明细里的"我们怎么走到这一步"是"因为……所以……"的账本：谁在哪个岗位干了几圈带来了什么、谁做完了哪张工单、哪个选择引出了哪张卡。让延迟后果读得懂，玩家才能自己讲出故事（Tynan Sylvester 的"故事生成器"）。

### 事件卡规格

每张事件卡是一条数据记录（`events/indian_wells/<id>.yaml`），引擎按字段决定它何时出现、怎么结算。写法见 `docs/content-guide.md`。

| 字段 | 说明 | 例子（`iw_sandstorm`） |
| --- | --- | --- |
| source | 里程碑、阈值、日历、后果、随机 | random |
| when | 出现的条件 | 大风天，且会员场能用 |
| cooldown / max_shown | 两次出现的最短间隔、一局最多几次 | 5 天 / 4 次 |
| countdown | 多久不处理就按默认处理 | 2 小时 |
| location / who | 发生在哪儿、谁来找你 | 会员场 / Dale |
| options | 2 到 3 个，每个有代价、效果、后续事件 | A：总监去会员场待 1 小时；B：场地状况 −25 |
| errand / cost / check | 选项要总监亲自去办、要花钱、要判定 | A 的 `errand` |
| default | 不处理时按哪个选项 | B |

设计检查清单：没有永远正确的选项（Sid Meier 的"有趣的选择"）；至少一个选项让短期和长期利益冲突；结果写进因果日志；尽量用现有活动动画演出结果。

## 参考与理论

| 参考游戏 | 借什么 | 用在哪里 |
| --- | --- | --- |
| Kairosoft（如 Pocket League Story、Game Dev Story） | 像素经营、小数值的爽感；等级主轴、多种解锁钥匙、日历节拍、赛事阶梯、软结局（[research-kairosoft.md](research-kairosoft.md)） | 整体手感；推进结构（提议） |
| Two Point Hospital / Campus | 修好一处、开出新玩法的节奏 | 设施修复和解锁 |
| Project Highrise、Prison Architect | 把人放到岗位上，需求按时段来 | 岗位和隐性排班 |
| Football Manager | 收件箱式事件、比赛日节奏 | 事件卡、表演赛 |
| Frostpunk | 倒计时危机、期限压力 | 事件倒计时、16 周期限 |
| Cultist Simulator | 即时制下的计时卡牌 | 非回合制的时间模型 |
| RimWorld | 叙事者控制节奏，游戏作为故事生成器 | 事件导演、因果日志 |
| Fallen London | storylet 与 quality 系统 | 事件数据结构 |
| Darkest Dungeon | 压力与怪癖 | 员工特质与士气 |
| 《八十亿分之一》（1 in 8 Billion） | 有出处的出身 + 一两个具体细节 + 在关键时刻被看见 | 人物背景、招聘卡（people.md） |
| RimWorld、Dwarf Fortress | 背景决定技能和特质；只说偏离平均的性格 | 人物的背景和特质（people.md） |

设计理论：

- **MDA 框架**（Hunicke、LeBlanc、Zubek）：先定玩家应该感到什么（废墟一点点复原），再倒推机制。
- **有趣的选择**（Sid Meier）：事件卡和招人的检查标准。
- **反馈回路**（Adams 与 Dormans，《Game Mechanics: Advanced Game Design》）：衰减和修复之间的拉扯；成功带来更多需求、人手又不够的负反馈。
- **兴趣曲线**（Jesse Schell，《The Art of Game Design》）：事件导演和修复顺序要画出的节奏。
- **Storylet / 基于状态的叙事**（Emily Short、Failbetter）：事件按状态挑选，而不是按顺序播放。
- **故事生成器**（Tynan Sylvester，《Designing Games》）：因果日志让玩家自己讲出故事。
- **不确定性**（Greg Costikyan，《Uncertainty in Games》）：天气、表演赛的判定、候选人的组合。
- **心流**（Csikszentmihalyi）：修好的设施越多、要管的人和岗位越多，难度随玩家能力逐步上升。

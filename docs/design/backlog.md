## M-0 重新设计游戏流程（设计，和 M-A 并行，M-B 之前）

2026-11-09 用户定下：2.5D 时期的主线（修复、16 周、星级、选路、幕、赛事和表演赛、地块、结局）和派工（原准则 5）整个作废（2026-11-12 文档删除），游戏流程围绕 3D 俱乐部重新设计，什么都还没定。
还站得住的和开放问题见 [game-design.md](game-design.md)「游戏流程：重新设计中」；下面一条一个问题，定了写回那一节，大的写 ADR。

- **一局和一天的结构：** 一次玩多久、一天在真实时间里多长；一件活、总监走一趟各算多少游戏分钟（场景是实时秒）。
- **目标和推进：** 有没有星级、等级、解锁；俱乐部怎么"变好"，在场景里长什么样；地图要不要长。
- **玩家在追求什么：** 一局有没有终点（期限、打分、赛事、无尽），赢和输是什么。
- **员工要不要有：** 要的话怎么来、怎么让他们干活；场景里的代客、教练、裁判、球童是氛围还是可以招的人；岗位和工单留不留；NPC 日常要不要由模拟驱动也跟着它。
- **事件和卡：** 还要不要卡、卡怎么来（U-13 的建议：有人走到总监跟前冒气泡）、errand 在直接操控下怎么做；现有 27 张卡都是为归档主线写的。
- **结算怎么接上场景：** 收盘卡上每一行在场景里看得到原因；没有派工以后服务率按什么算（归档那套的算法在 `docs/archive/2.5d-game/packages/sim/src/day.ts`）。
- **失败状态：** 有没有破产、会员走光、设施停用；没人管的地方乱到什么程度为止（准则 5）。
- **定了以后重写模拟：** 2.5D 的模拟、内容、界面、游戏 app 2026-11-12 整套归档在 `docs/archive/2.5d-game/`；按新流程重写，好的做法（种子随机、事件引擎、存档迁移、内容编译校验、机器人跑局）照着重写，不引用。

### 每个场景剩下的

- **clubstadium · 要定的小事：** 球童静态画面里还是缩到 0.74（玩法里已是少年比例 1）；大伞挡住坐在外侧椅子的人；杯子小；一圈 ≈ 5 分钟嫌不嫌长；散场后球童收伞（每场都要重新撑伞补水）要不要 —— `lab/clubstadium.md`「stage 3」→「还没解决的 / 要商量的」。
- **clubcourts · 收尾：** 拎着的捡球篮像拖在地上（要一个提起来的握法 / `carry` 姿势）；截击只有平飞球、换边不去水站；对着空场吹看不出在吹；风补沙的速度、抱怨还没接到玩法节奏和结算 —— `lab/clubcourts.md`「stage 3」的「还没解决的」。
- **clubfood · 收尾**（stage 2 + 3 做完了，剩下的）—— `lab/clubfood.md`「还没解决的」「要用户定的」：
  - 要用户定：院子地面换成暖一点的"红砂碎石"（`yardGranite`，饱和度到 0.43 靠它）；伞影落不到野餐桌上（伞挪还是换侧挂伞）；摊主露脸要不要把四辆车的窗上沿抬到 ~2.6；厨房后门要不要放一只看得见的大垃圾箱。

## M-B 重写模拟，场景接回游戏

M-0 定下的游戏流程决定这里的具体做法；下面是不管流程怎么定都要做的。

- 按 M-0 的结论重写模拟（`packages/sim`）、内容（`packages/content`）、界面（`packages/ui`）和游戏 app（`apps/game`）；分层照旧：apps → ui → sim → shared，sim 不碰画面。
- 写场景接口 ADR（ADR 0027 要求的）：游戏只认接口，不 import 某个场景；锚点 → 场景、站位、区域、相机预设、演出入口 —— [architecture.md](architecture.md)「接回游戏」。
- 锚点直接用场景的名字（`outer_2/3`、`practice_w/e`、`pickle_1/2`、露天前台、餐车院子……），走路的距离从 `clubsite/world.ts` 的步道量。
- 总监的活 ↔ 模拟命令：互动点做完 = 一条命令；按住的活按游戏分钟累计；实时秒 ↔ 游戏分钟的换算（数在 M-0「一局和一天的结构」里定）—— ADR 0029。
- 结算、卡（如果留）、NPC 日常要不要由模拟驱动，按 M-0 的结论接。
- 场景里的脏乱（沙、水洼、球、线、裂缝）由模拟的量驱动，总监在场景里扫 = 模拟里的一次打扫。
- three 进游戏 app：改 `three-only-in-sandbox` 规则；场景代码从 sandbox 挪进一个包，sandbox 和游戏都从包里拿。
- 游戏的画面：场景 + HUD + 总监操控的按钮放在一起（拇指区不打架），竖屏横屏都要。
- 测试：确定性、机器人跑局、有无画面一致、评审代理在 3D 场景里操控总监 —— [testing.md](testing.md)「接回游戏时要补的测试」。
- 场景状态要不要存档（场面、叶子、谁手里拿着什么）。

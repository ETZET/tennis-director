## 怎么派

### 能力档位

每个任务标了做它需要的能力。高层要求，不是硬规定：

| 档位 | 谁来做 | 适合什么 |
| --- | --- | --- |
| **A** | 最强的模型（Opus 5.5） | 要审美判断、看截图反复迭代的事（所有美术）；要拿主意的设计（写卡、定数值、取舍）；评审"好不好玩"；动到多个包的改动 |
| **B** | 上一代主力模型也能干 | 边界清楚、有现成模式可以照抄的事：简单界面改动、按规格改模拟、补测试、工具脚本、按模板加内容 |
| **C** | 轻量模型就够 | 机械性的事：重跑报告、文案校对、两种语言对齐、格式修正 |
| **人** | 你 | 拍板、真人试玩、只能在 GitHub 网页上做的操作 |

### 每个任务的子 agent 都要有

- 读 `CLAUDE.md`、本文对应的那一条、和它点名的文档或 ADR；不读别的轨道的任务。
- 在自己的分支上做，开 PR，**CI 全绿**才算完成（类型检查、Biome、分层规则、测试、构建）。本地装不上依赖时，用 CI 验证。
- 改了数值要重跑平衡报告（`pnpm sim bots`），平衡区间（`balance.test.ts`）不能破。
- 不改别的轨道的文件（见每条轨道的"改哪里"），避免互相冲突。界面任务只加 `ui.*` 文案键；玩法任务才改内容 YAML 和其他文案。

### 环境需求

| 标记 | 意思 |
| --- | --- |
| 截图 | 能构建游戏、在无头 Chromium 里截手机（390×844）和桌面图并**看图**判断（Playwright 或试玩桥 `/shot`） |
| 试玩桥 | 能起 `tools/playtest/server.mjs`，通过 HTTP 玩完一局 |
| 跑局 | 能跑 `pnpm sim bots` / `playability`（几分钟） |

### 并行

四条轨道可以同时开工：界面改 `packages/ui`、`apps/game`；玩法改 `packages/content/data`；逻辑改 `packages/sim`、`packages/content/src`、`apps/sim-cli`、`tools`；美术改 `packages/iso`。跨轨道的依赖写在每个任务的"依赖"里。**第一步是 GM-1 评审**：很多调整要等它的结论。

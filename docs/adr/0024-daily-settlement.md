# 0024 每日结算：钱、声望、会员每天收盘按今天结算，停下来弹一张结算卡

- 状态：提议（2026-11-06 制作人拍板，wave 0 契约见 `docs/design/daily-settlement-contract.md`）
- 日期：2026-11-06
- 修改：准则 6（"会员、声望不实时漂移，按一周的平均服务率结算"）；补充 [0012](0012-staffing-loop.md)、[0017](0017-grade-drop.md)、[0022](0022-court-usability.md)

## 背景

到现在为止钱按天记账，但声望和会员只在周日收盘按这一周的服务率结算一次（GM-1 的周结算，一条因果日志、一条快讯）。
试玩里玩家一周有六天看不到自己排人排得好不好落在了哪里：拖了一天人，数字不动；周日一下子跳一截，原因压成一行快讯，
没人读完。玩家也没有一个"今天收工了"的时刻。

## 决定

- **每天收盘结算一次**：钱（已经是按天的）、声望、会员都只按**今天**的情况算：今天的服务率、今天走掉的会员、今天的特质。
  公式在内容 `rules.day`（代替 `rules.week`），初值是周结算各项 ÷ 7（按周累计的量：服务、质量、修复；按次数的量不除：今天走掉几个就是几个）。
  会员按小数算，取整以后的零头留到明天（`memberCarry`），不丢。会员上限、"一天最多走掉几个"也挪到每天。
- **今天没有需求就不动**：一整天没有一个开着的有需求岗位（开局、雨天全关）时声望和会员都不结算（准则 6：没人就是零、不倒扣）。
- **停下来弹一张结算卡**（不管几倍速）：像素风，数字滚出来；点一下跳到结尾，再点一下进入明天。卡上只报告，不让玩家选（准则 1、4：
  不加菜单式操作）。内容：今天的钱按来源拆开、声望和会员各自为什么变、今天的人（干得最多 / 一直闲着 / 士气在掉，像素头像）、
  明天的预告（天气、可能变脏的球场、赛事和招聘日、离季末还有几天）。
- **明天的天气收盘时就抽好**（存进状态），所以预告是真的；抽签的随机数顺序和以前在开门时抽一样。
- **周结算只剩回顾**：`settleWeek` 不再改任何数；周日的结算卡多一页"本周回顾"（七天加起来、最好和最差的一天、服务率走势）。
  掉档（ADR 0017）照旧在周日；招聘日、赛事不变。
- **模拟从不等卡**：`daySettled { report }` 只是领域事件。游戏自己停钟、点完再走；不是命令，不进命令日志，重放和界面无关。

## 后果

- 准则 6 改成"钱、会员、声望不实时漂移，每天收盘按今天的服务率结算一次，今天没有客人就不动"（CLAUDE.md、game-design.md 同步）。
- 一天的变化很小（声望一天零点几、会员多半是 0–2 个），但每天都讲得出为什么；一天没排好人，当晚就看得见。
  代价是更容易被"某一天运气不好"影响：没有平滑，公式按今天算（风险和对策见契约"风险"一节）。
- 模拟：新状态 `today`（今天的账）、`memberCarry`、`forecast`、`days`（最近 7 份报告）；新因果日志 `daily`；领域事件 `daySettled`；
  变量 `service_rate`、`service_demand`、`care.walkouts` 改成按今天（名字不变）；存档 14 → 15。
- 游戏：每天停一次，一局 112 天就是 112 张卡，必须一下就能点过去（第一下跳到结尾、第二下继续）。调试跳过好几天时只开最后一张。
- 机器人不受影响（它们不看卡）；平衡会变（每天按小数结算、每天 `max(0, …)` 比每周一次稍宽），由代理 A 守住 `balance.test.ts`。

# 0009 内容工具和平衡（M3）

- 状态：已采纳
- 日期：2026-10-30

## 背景

技术文档 M3：热重载、调试面板、内容校验、机器人跑局报告。闸口是"策划能在不写代码的情况下加一张卡"。

## 决定

- **内容热重载**：`@td/content/vite` 的 `contentHotReload()` 插件盯着 `data/` 下的 YAML，保存后重新编译。通过就用自定义 HMR 事件 `td:content` 把新内容包推给页面，游戏调 `setContent()` 换上，不刷新、不丢进度；失败就弹 Vite 错误层，写清文件和问题。生成的 JSON 不在这里写，提交前照常 `pnpm content`。
  - 插件从工作区 TS 源码导入编译器，所以 `apps/game` 的 Vite 用 `--configLoader runner` 加载配置。
  - Node 专用的读目录函数放在 `@td/content/node`，不从包入口导出，浏览器包里不会混进 `node:fs`。
- **调试面板**（`@td/ui` 的 `DebugPanel`，开发版或 `?debug`，按 \` 开关）：改状态量和标记、看导演此刻可能抽到的卡和概率并强制打开、看日程、跳时间、导出存档和命令日志、用指定种子开新局。所有改动都走模拟的 `debug*` 命令，进命令日志。
- **内容校验**加了一条：一种语言有、另一种没有的文案键给警告。
- **平衡**：机器人报告的目标是贪心型通关 80–90%、随机型 8–15%、每张卡都出现过。调整：董事会信心的公式变缓；表决成功率封顶 85%（缺席投票 75%），再差也有 12%（缺席 8%）；会员日变化的中点从质量 50 降到 46。结果（各 1000 局）：贪心 83.7%，随机 10.4%。`apps/sim-cli/src/balance.test.ts` 用 200 局守住一个更宽的区间。
- **闸口示范**：`hc_rival_flyer` 只加了一个 YAML 文件和两种语言的文案。写错字段类型时（`weight` 写成字符串），编译器报出了文件和字段。流程写在 `docs/content-guide.md`。

## 后果

- 加卡、改数值、改文案都不用改代码；新增"一类"效果或条件仍然要改 `@td/sim` 和 schema（ADR 0007）。
- 平衡改动要附上新的 `docs/balance/hollow-creek.md`。

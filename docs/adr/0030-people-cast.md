## 背景

clubwalk 把 11 个场景连成一整座俱乐部，场景里一共约 238 个 Q 版人（含相邻区域藏着的副本）。他们由各场景的 `life.ts` 按脚本演：排队、打球、坐着看、吃饭、游泳。
但他们只有球员 v0..3 四套衣服，没有名字、没有身份；点一个人什么也得不到。

2.5D 时期写过一份人物模拟（`docs/archive/2.5d-game/docs/people-sim.md` v3，ADR 0028）：三层人、行为是信号、不流于随机、关系成对、常客有来访模式和记忆。
方法论站得住，可整份建在派工上（岗位、习惯、回班、空闲产出、招聘日互斥）和 16 周主线上（星级、选路、赛事、第二季），2026-11-09 一起作废。

用户 2026-11-13 要：把那份设计净化成 3D 版；造出多得多、丰富得多的人；每个在场景里出现的人都有属性；clubwalk 里有一份会员名册，能和他们互动，在场景里点人也能互动。
用户同时说：做原型可以违反玩法准则（先找好玩），冲突处在文档里写一句；名册是看信息的菜单，互动尽量要求总监走到人跟前。

## 决定

1. **人物身份是一层演员表，叠在演出上。** 演员表（`apps/sandbox/src/clubsite/cast/`）是纯数据 + 纯函数：不 import three、不碰 DOM、不用 `Math.random` / `Date.now`，状态可序列化。
   以后重写模拟（M-B）时整个搬进 `packages/sim`。契约在 `cast/types.ts`（冻结），特质表在 `cast/traits.ts`。
2. **场景的 `life.ts` 继续演，演员表只回答"这个位置今天是谁"。** 位置按名字引用：场景 + 槽位（`slot:<id>` 去掉前缀，演出临时建的人是 `'#<n>'`），不按坐标（同"模拟只按名字引用位置"）。
   `who(scene, slot, kind, day)` 给出一个人，画面层按他的 `CastLook` 给已经建好的 Q 版人换装（`clubsite/people/dress.ts`），再挂名字、属性、"在想什么"。
   一期演出不读演员表（谁在哪儿还是 `life.ts` 说了算）；二期起常客按来访模式进出，演出跟随演员表。
3. **三层人。** `named`（有名有姓、手写故事：员工、老会员、常客、他们的家人）· `regular`（有名字、有属性、按模板生成的熟面孔，固定种子，每局一样）·
   `crowd`（今天的客人，按 种子 + 场景 + 槽位 + 天 生成，同一天同一位置永远是同一个人）。三层都是完整的 `CastPerson`：每个出现在场景里的人点开都有身份和属性。
4. **不流于随机。** 生成、选角、"在想什么"挑哪一句、互动的结果都只用种子哈希；同一个人在同样的处境下做同样的事、说同样的话。
5. **名册是看信息的菜单，互动要当面。** 名册列 named + regular（见过面的客人也可以进），只读：谁、在哪儿、属性、特质、牵连、最近的记忆，外加一个"走过去"（寻路到他今天的位置）。
   六个互动动作里五个要总监在他跟前（约 3 米以内，`ActionDef.inPerson`），不在跟前按钮变成"走过去"；只有"发条消息"能在名册里做，效果最小。
6. **好感、心情、记忆是演员表的状态（`CastState`），现在不碰任何经营数。** 没有模拟，就没有钱、会员、声望可碰；接回以后好感只影响耐心、带朋友和卡（沿用 0028 的边界），碰经营数的例外要逐条列在设计文档里。
7. **一天的时钟是 demo 自己的。** `CastState.day` / `minute`（营业 7:00–22:00，第 1 天是周一）只用来换天（换人群、算周几、"同一天说多了"）；它不是 M-0 要定的"一天的结构"。

## 和玩法准则的关系

- **准则 1（不做菜单式操作）——有偏差，demo 阶段允许。** 名册是从 HUD 打开的一个菜单。收紧的办法：名册只读、不做管理操作；能改变人的动作都要当面（走过去、点人）；
  名册里唯一的远程动作"发条消息"效果最小（好感涨得最少、讲排场的人嫌敷衍），它省掉的是走路，代价是效果。
  接回游戏前要再评审：名册留不留、留成什么样（例如总监的小本子：只在 HUD 上一个按钮，打开只看不点），以及"走过去"算不算菜单操作。
- **准则 2（选择要有取舍）。** 每个动作都有付出：钱（请客、送礼）、游戏分钟（打一局最贵）、总监的位置（他站在这儿聊天，别处的活就没人干——ADR 0029 的取舍）、好感的风险（打扰正在打球 / 干活的人、同一天说太多、特质不对路会扣好感）。
  没有一个动作对所有人都最好：特质改倍率，好胜的人爱打一局、老伤的人推掉，吃货爱被请、节俭的人不好意思。
- **准则 3（选择留下痕迹）。** 每次互动在他的记忆里留一行（名册"最近"），好感和心情变；"听听意见"会让名册多出牵连。demo 里还没有因果日志，也没有后续卡，痕迹只到人为止；三期的人物卡补上。
- **准则 4（事件偶发、有分量）。** 互动是玩家主动的，不是卡，不受节流；三期的人物卡照准则 4 节流（每周最多两张），纯奖励的时刻做快讯不做卡。
- **准则 5（不操作时世界照样运转）。** 演员表不让任何经营数实时漂移；心情按天回到底子，好感只在互动时变。人群每天换，常客按自己的每周模式来，不因为总监不理他们就消失（`gone` 只由卡或剧情触发，沿用 0028）。

demo 阶段另外两处和以后的游戏不一样，都只在 sandbox：总监的零用钱（`CastState.money`）是 demo 的数，不是俱乐部的账；互动花的游戏分钟只推 demo 时钟，不影响场景演出。

## 后果

- 新目录 `apps/sandbox/src/clubsite/cast/`（演员表、特质、名单、生成、选角、互动规则），`clubsite/people/dress.ts`（按 `CastLook` 换装）、`clubwalk/cast/`（对上场景里的人、名册、点人、互动界面）。
  `clubsite/people` 给每个人加了 `userData.isPerson`、`poseName()`、`personKind` / `personVariant`，演员表按它们在场景里找人、推断"在干什么"。
- 场景不改：`life.ts` 照旧演，没有演员表时一切照旧（`cast` 关掉 = 原来的四套衣服）。改场景的槽位名会让演员表对不上，场景改 `SLOTS` 时要同步 `cast` 的位置表（有测试兜着）。
- 分层：`clubsite/cast` 只被 `clubsite/people/dress.ts` 和 `clubwalk` 引用，自己不引用 three、场景和 `clubsite` 的其他模块（types 除外），建议在 `check:deps` 里加一条 `cast-is-pure`，M-B 搬家时改成 `sim-is-pure` 的一部分。
- M-B 接回游戏时：演员表、`CastState`、互动规则搬进 `packages/sim`（`act` 变成一条命令，结果是领域事件）；换装、名牌、名册、点人留在画面层和 `packages/ui`；名册的界面文字走 i18n。
- 0028 里作废的部分（空闲产出 `idle_k`、回班、习惯、招聘日互斥和可达性、周结算、存档版本、人物卡的具体选项）不带过来；要重新做卡时按 M-0 的结论重写。

# 0013 地点牌：一个地点一块牌，岗位和工单收进拇指区的地点清单

- 状态：已采纳
- 日期：2026-11-01
- 修订：[0012](0012-staffing-loop.md) 的「界面」一节（岗位轮廓、工单标记各自挂在场景里）

## 背景

0012 上线后在 390×844 上开局截图：场景里同时挂着 13 个一模一样的 ⚒ 工单标记，外加岗位圈和地点小圆点。
1 号场一个地点就有 4 个岗位、7 张工单，标记按"叠住就往上让"一路堆成一根柱子。玩家看不出哪个 ⚒ 是什么，
也够不准——标记小、挤在岛中间，正好在拇指够不着的上半屏。拖人的时候所有标记一起亮，等于没提示。

根子不在样式：**一个地点的工作量会随内容一直涨**（新岗位、新工单、招聘后的岗位），按"一项工作一个标记"摆，
标记数和内容量成正比，手机屏幕一定会被淹没。补丁（缩小图标、让开、只显示开了工的）只能推迟问题。

## 决定

**一个地点一块地点牌（hub）**，场景里最多 8 块（锚点数），和内容多少无关。

- 地点牌上只放"一眼要知道的"：每个此刻要人的岗位一格（在岗的人的头像带环形进度，空着要人是红色 +），
  再加一格工单数 `⚒N`（有开了工的就显示最高进度）。工单格按能力上色（教学黄、维护绿、服务蓝），
  和员工条上的能力条同一套颜色，看一眼就知道该派谁。
- **点地点牌**：在拇指区弹出这个地点的清单（地点名 + 每项工作一行：名字、状态、进度、谁在干、要多少钱）。
  点一行打开原来的说明（0012 的 TargetSheet），× 回到清单。
- **拿着人点地点牌，或把人拖到地点牌上松手**：
  - 这个地点只有一项这个人能接的活 → 直接派过去（一步完成，和以前一样直接）；
  - 有好几项 → 弹出同一个清单，人还拿在手上，每行标出"这个人去了能力多少、走多久、会放下什么"，点一行派过去；
  - 一项都接不了 → 清单里每行写清为什么（钱不够、人满了）。
- 清单里的每一行也是落点：拖着人直接放到行上就派过去。
- 拿着人的时候，能接活的地点牌描黄，接不了的变暗；没东西的地点不出牌。

## 为什么不违反准则 1（不做菜单式操作）

清单是**点场景里的东西**弹出来的，它本身就是那个地点的"近景"：一行对应场景里一处工作，没有分类页、没有子菜单，
派人仍然是"拿人 → 放到地方上"。只是把落点从岛中央挤成一团的小标记，挪到了拇指够得着、44 px 以上的行上。
常见情况（地点只有一项能接的活）仍然一步到位。

## 后果

- `apps/game/src/main.ts`：岗位、工单标记换成每个锚点一块地点牌；有地点牌的地方不再画地点小圆点。
- `apps/game/src/session.ts`：多一个 `place`（打开的地点清单）。
- `apps/game/src/project.ts`：`placeSheet()` 生成清单快照；`packages/ui` 新增 `PlaceSheet`。
- 试玩桥：`state.targets` 列出地点牌（`target` 是锚点 id）和清单里的行；`/tap/<锚点>` 等于点地点牌，
  `/tap/<岗位或工单>` 仍然直接点那一项。
- 以后加岗位、工单不会再让场景变挤；清单行数多了也只是在拇指区里滚动。

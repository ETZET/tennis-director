# 0012 核心玩法转向：招人和排人（取代 0011 的公告板、动作圈和精力）

- 状态：已归档（2026-11-09：主线 / 派工归档，游戏流程重新设计），见 [main-line-2.5d.md](../archive/pre-3d/main-line-2.5d.md)；归档前是"已采纳"
- 注：本文定的原准则 5 归档在 [tenet-5-staffing.md](../archive/pre-3d/tenet-5-staffing.md)；`staff.ts` 等实现照旧在跑，重新设计定了再删改。
- 日期：2026-11-01
- 取代：[0011](0011-management-loop-v2.md) 中的日程公告板、现场动作圈、总监精力、"总监跑过去"；季节、天气、偶发事件、
  不操作时不漂的结算方式保留。

## 背景

第一轮试玩（`docs/archive/pre-3d/backlog-indian-wells.md` 的 R1–R10）给 v2 循环打了 5.0 和 4.4 分。问题集中在：公告板上有一套通吃的日程（R1）、
精力从来不紧、后期钱没处花（R7）、幕中段张力消失（R2）、免费或被压制的选项（R4）。负责人 10-31 晚定下转向
（当时 `docs/design/game-design.md` 的「核心玩法决定」，现归档在 `docs/archive/pre-3d/game-design-v0.5.md`）：否决叙事卡牌游戏和"总监走来走去"，改成经营模拟，核心是**招人 + 把人放到该在的地方**；
总监是可分配的劳动力；没有字面上的日程表；一次性岗位（工单）和持续岗位分开；准则 6 改写为"没人管的地方慢慢变差"。
11-01 负责人接受了这份 ADR 里的五条细则建议。

## 决定

**循环（四个时间尺度）**

- **几秒：** 场景里看得见需求（空位轮廓、排队的人、杂草）→ 把人拖到岗位或工单上 → 看进度 → 出收益。
- **一天：** 需求按时段来（早上退休会员、下午放学孩子、傍晚上班族）。岗位只在自己的时段里有客人，人手比岗位少，玩家一天重派两三次；排班就藏在拖动里。
- **一周：** 周日收盘按本周平均服务率结算会员和声望；设施状况按使用量衰减；隔一两周有招聘日或试训日（事件卡）。
- **一幕：** 开局只有总监和 Dale；修好设施会开出新岗位，会员多了还会开出更多岗位，所以要招人，工资压着现金。总监从"干活的人"变成"排人的人"。

**五条细则（11-01 拍板）**

1. **员工维度最小集：** 三项能力——教学（沿用 `skill`）、维护（`upkeep`）、服务（`service`），每项 0–100；另有工资和特质。士气只属于员工，总监没有士气，能力随干活慢慢涨。
2. **重派要花走路时间：** 员工按导航图走过去（固定速度，不再有精力），到了才开始干。这是拖动的主要代价。
3. **没人服务的需求不倒扣流量，但拉低本周服务率：** 收入和满意度增量只在有人在岗时产生（准则 6）；没人服务的需求分钟计入服务率的分母，周末按平均值结算会员和声望，属于"存量按平均状况结算"，不是实时漂移。
4. **节奏：** 1× 下一个营业日约 2 分钟（原来约 1 分钟），所有有需求的岗位都有人、又没有工单进行时才加速。
5. **试玩第二轮在新循环上做：** 第一轮的 R1、R7 随公告板和精力一起去掉；R2–R6、R8–R10 中仍然适用的条目在新循环上重新检查。

**模拟（`packages/sim`）**

- 状态：`people[*]` 加 `upkeep`、`service`、`post`（指派到哪个岗位或工单）、`at`/`walk`（站在哪、走在哪段路上）；总监是 `people.director`。
  新增 `posts`（持续岗位每一圈的进度）、`orders`（工单进度）、`condition`（设施状况 0–100）、`week`（本周需求分钟和服务分钟）。
  删除 `director`（走位和精力）、`plan`、`planning`、`actions`。`SAVE_VERSION` 升到 3，旧档迁移时把总监和 Dale 放到原地、无指派。
- 命令：`assign { person, target | null }` 取代 `moveDirector`、`act`、`setPlan`、`lockPlan`。
- 每个 tick 的系统顺序：日历 → 员工走路 → 岗位和工单推进 → 活动 → 质量 → 事件 → 导演；收盘时：衰减 → 经济 → 周结算。
- 持续岗位被拉走：这一圈的收益作废，这一圈已经算作"有人服务"的分钟退回成"没人服务"。一次性工单被拉走：进度保留。
- 设施状况：每天按 `decay_day` 衰减，岗位每圈的 `wear` 额外磨损；维护类岗位每圈恢复。状况低于 60 只出画面信号，低于 30 时设施的质量贡献减半，到 0 时为零；状况低于工单的阈值时工单冒出来。

**内容（`packages/content`）**

- 新增 `data/posts/*.yaml`（持续岗位：地点、能力、圈长、时段、需求条件、每圈收入、服务、磨损或修复、效果、演出）和
  `data/orders/*.yaml`（工单：地点、能力、工时、材料费、出现条件、完成效果、能否多人、演出）。
- `data/actions/` 删除，大部分改写成工单；`activities` 的 `program`（上公告板）删除；幕的 `schedule`、`energy` 删除，加 `demand`（时段需求）和 `staff` 开局名单。
- 效果 `energy`、条件 `directorAt`、选项 `requiresDirectorAt` 删除；新增条件 `assigned { person, at }`（谁在某个地点干活）。
  `COMPUTED_VARS` 加 `service_rate`、`condition.<设施>`、`staff`（在职人数），删除 `director.energy`、`plan.*`。

**界面（手机优先）**

- 人头顶有名字牌，长按拖动到岗位轮廓或工单标记上；拇指够不着时用"点人 → 点岗位"两步指派。目标至少 44 px。
- 持续岗位：场边固定的空位轮廓，头顶环形进度；一次性工单：长在问题上的工具标记和直条进度（设计文档「已接受的方案」）。
- 公告板和动作圈从界面上删掉。

## 后果

- 机器人改写：贪心（按需求时段排人、先做收益最高的工单）、随机、放置不管。平衡区间暂时放宽，等新循环调完再收紧；
  `docs/balance/hollow-creek.md` 重新生成。
- 卡片退为点缀：引用精力、总监位置的选项改成按"谁在某处干活"或直接去掉。招聘日和试训日是卡。
- 渲染层只多了岗位轮廓、进度环、工单标记三样读状态的东西；演出照旧走活动动画库。
- CLAUDE.md 的玩法准则第 5、6 条随之改写。

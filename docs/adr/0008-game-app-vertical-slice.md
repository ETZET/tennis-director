# 0008 游戏 app：第一幕纵切片（M2）

- 状态：已采纳
- 日期：2026-10-30

## 背景

技术文档 M2：第一幕可以从头玩到尾。15–20 张卡、总监走位、因果日志、活动演出。闸口是试玩。

## 决定

- **运行时（`apps/game/src/session.ts`）**：持有 `GameState` 和命令日志。1× 每秒 4 游戏分钟，2×、4× 按倍数。一分钟一分钟地调 `advance()`，模拟发出 `requestPause`（要紧的卡）就停在那一分钟，不会一帧跑过头。玩家命令先排队，暂停时也立刻生效。
- **"先走过去"的选项**：按下要总监在场的选项时，先发 `moveDirector`，记下意图；总监一到、选项还可用，就替玩家发 `chooseOption`。两条命令都进命令日志，重放结果一样。卡片上这类选项不锁，显示走路图标和"要先走去 1 号场 · 38 分钟"。
- **投影（`project.ts`）**：模拟状态 → HUD 快照。玩家眼前那张卡是最快过期的那张，后面排着几张显示在标签上。"因为……所以……"由因果日志的原因和效果拼成，放在俱乐部报告里；快讯带由领域事件攒出来（不进存档）。
- **画面（`scene.ts`）只读模拟**：总监沿 `hollow-creek/layout.ts` 的路径折线插值（模拟的步行分钟数由折线长度 ÷ 1.5 米/分钟得出，测试保证两边对得上）；主教练总监不在场时低头看手机（专注度低于 0.6）；设施换状态就显示对应的覆盖层；活动的 `performance` 名字对应一段演出（对打、人群、拔河）；2 号场租给匹克球时一直有人在打。演出用自己的时间轴，暂停时停、变速时不跟着快进。
- **地点牌**：每个锚点一块，点一下总监就走过去；总监在这儿是绿色，正走去的地方亮黄，有卡的地方带感叹号。
- **文案**：游戏界面的文字也进 i18n（`ui.*`），`?lang=zh` 切中文。HUD 组件自己的少量标签暂时还在 `@td/ui/strings.ts`。
- **存档**：IndexedDB 自动存档，收工和每 30 秒一次；打开页面有存档就接着玩，`?new` 或 `?seed=` 开新局。

## 后果

- 第一幕可以完整玩到结局（三个通关结局、卖掉、卖给开发商、破产）。
- 画面层不碰模拟，读档后 `sync()` 一次就能把演出对齐到任意状态。
- 只有 Hollow Creek 有场景模块；其他幕要先有自己的 `STANDS` 和路径。

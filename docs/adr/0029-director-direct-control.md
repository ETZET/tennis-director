## 背景

0012 起总监是一个可指派的劳动力：玩家把他的头像拖到地点牌的岗位或工单上，他按步道走过去，干完一圈结算一次。
2.5D 画面里这个人很小，玩家看不到他在干什么，"总监在哪儿"这件事只在数字里。

2026-11-07 起在 sandbox 里做 3D 像素场景，desert3d-v2 先做了"总监能走、能拿工具、能扫场"，后来泛化成 `clubsite/play/`，
五个俱乐部场景接上了：停车场的代客、露天前台签到递毛巾、匹克球场绷网捡球、红土场拖场扫线浇水、喷泉广场捞叶子扫地浇花。
每个场景的 NPC 有自己的日常（`life.ts`），会因为总监在不在、做没做而变：队伍排长、水站空了有人抱怨、叶子多了长椅上的人走掉。
用户 2026-11-08 看过以后定下：一切以这些 3D 场景为准，直接操控总监就是现在的玩法。

## 决定

1. **玩家直接操控总监。** 拖动 = 摇杆，点地面 = 寻路走过去（A* + 拉直），相机跟着总监；动作键（大按钮，桌面空格 / E）、拿/放键（小按钮，F / 回车）。不加菜单（准则 1）。
2. **活是场景里的东西。** 一件活 = 一个互动点（`play.add`：走近才出按钮，一次性的按一下、持续的按住）或手里的一件工具（`play.addItem`：拿起来走，用它干活）。干的结果直接改场景的状态（场面、水位、叶子、钥匙在谁手里）。
3. **NPC 的日常自己跑，只读总监。** `life.ts` 按演出时钟和种子随机流推，读总监的位置、手里的东西、做完了什么，作出反应；不读别的场景。
4. **取舍就是总监站在哪儿。** 同一时刻他只能在一处；他不在的地方按各场景的规则慢慢乱（准则 2、6）。每个场景的"不管会怎样"写在场景文档和 `docs/design/game-design.md`。
5. **手机优先，竖屏、横屏都要。** 每个场景给两种取景；按钮在右下拇指区（现在 ≥ 56 px，底线 44 px）；桌面加键盘（WASD / 方向键走，空格 / E、F / 回车）是第二布局。
6. **员工照旧靠招人和排人（准则 5）。** 员工在 3D 里怎么派（拖头像到场景里的岗位、让总监去"叫"人……）和总监的活怎么对上模拟，接回游戏时另写 ADR 定（场景接口）。
7. **数值仍由模拟决定。** 接回以后，总监做完的一件活变成一条模拟命令（例如派到一个岗位、一次打扫）；场景里的演出只负责演。现在 sandbox 顶栏上的数字（队伍、水位、场面）只是演出用的，不进存档、不结算。

## 后果

- 场景接回游戏（backlog 的 M-B）要定：互动点 ↔ 模拟的岗位和工单、场景里的站位 ↔ 模拟的锚点、总监走路的实时秒 ↔ 模拟的游戏分钟、卡的 errand（选项把总监叫走）在直接操控下怎么做。
- 准则 5 里"把人（总监也是一个可指派的劳动力）拖到岗位"的写法和直接操控不完全一样；措辞要不要改，等接回游戏时由用户定（准则本身照旧适用）。
- 没有"总监的活"的场景也要有：每个新场景按 pixel-scene 流程做到 stage 3 时，至少给总监两三件有取舍的活。
- 操控代码只有一份（`clubsite/play/`），场景只登记自己的互动点和工具；desert3d-v2 的 `control.ts`、`hud.ts` 保留作实验记录，不再扩展。
